# Provider 内容风控拦截（400 Content Exists Risk）：机制、定位与处置

## 机制

- **审核在输入侧**：整条请求体（system prompt + 全部历史消息 + 工具返回内容）一起过风控；命中即返回 400，**模型根本没运行**。所以「重试 / 换说法 / 降温度 / 调参数」全部无效。
- **自锁效应（关键）**：命中片段进上下文后永久钉在会话历史里，之后每次请求原样重发 → 该会话此后每次都撞。主人的表述是「只要让你去查就会报错」——**查这个动作本身把敏感原文灌进了上下文**。
- **量级决定概率**：零散提一个词通常不触发；**成段全文**（技能文档、配置清单、订阅节点表）命中概率高得多。这解释了「以前用挺久都没事」——以前没成段进过上下文。

## 已知高敏内容类型（实测）

代理 / 机场 / VPN 订阅类文本，最典型的是代理运维技能全文 + 节点清单（线路名、剩余流量、套餐到期）。
反面对照：涉政人物/机构/历史事件、色情描写、暴恐、赌博毒品类实质文本**都没有**命中；「杀（kill 进程）」这类普通用词也不触发。

## 定位三步（可复现）

1. **拿失败请求的完整 body**
   - `/opt/data/sessions/request_dump_*.json` —— 被 400 拒的那次完整请求体
   - `/opt/data/state.db` 的 `messages` 表 —— 按 `session_id` 取该会话逐条消息 + 时间戳
2. **按时间戳做 diff**：取「首次 400 的时刻」，找**在此之前新进上下文、而更早的成功轮次里完全没有**的那几条消息 —— 那就是差异因子。
   - **执行方式（不污染主会话）**：写一个**只打标记**的脚本，逐条消息只 print `index / role / len / 时间戳` + 每类候选敏感词的正则**布尔值**（如 `proxy_terms`、`ip_port`），**绝不 print content**。diff 照样做得成，主上下文却干净（实测可行：定位到触发会话，主会话全程没撞）。日志侧同理只取时间戳与 session_id：`grep -n "Content Exists Risk" logs/errors.log | cut -c1-140`。
   - **对齐「刚进来的那条工具输出」**：400 常常发生在某条工具结果落地后的同一秒（实测工具输出 10:45:35 落地、同秒 400）——拿工具输出时间戳对首次 400，比看消息序号有用。
3. **对照组**：另开一条全新会话聊同一话题，正常返回即证明**话题词本身无辜**。审核是黑盒且非确定，所以「时间线强相关 + 干净对照组」是在这个黑盒里能拿到的最硬证据。

## 处置

- **不要在被污染的主会话里 grep 那些原文**——读取本身就是把雷踩实。派**子代理**去读（独立上下文），任务书写明：回报**不复述敏感原词**，只给文件位置与结论。
- **需要继续干活 ≠ 需要主人开新会话**：子代理和 cron 都有自己的上下文，可以直接承接后续任务；只有「这条主会话本身还要接着用」时才 `/new`。
- 单条会话已污染的两条出路：`/new` 开干净会话，或切 provider（换家即绕开，与内容无关）。**但 `/new` 只在读法同时改变时才算解**——新会话重跑同样的读取命令等于重新埋雷，会陷进「换会话→又撞」的循环。
- **结果回传形态**：让子代理写**只含布尔/计数/码值/哈希**的结果文件，父级读文件 + 跑一条端到端命令核验；不要为了「验证」把原文拉回主上下文。
- **子代理同样会被打中**（同 provider、同样整条请求体过审）：任务书里除了「只回报脱敏结论」，还要指定**只含布尔/数值的结果文件**由父级读取核验，并明确禁止 `cat` / `read_file` 原文；它真被 400 打断时，废的是它那条会话，父级照常按结果文件复核。
- **主会话也能自己干：写「脱敏探针」而不是「抄原文」**。凡是不需要人读原文、只需拿结论的活（连通性、计数、结构指纹、时间戳），写成只 print **计数 / 类别 / 布尔 / md5 前 6 位** 的脚本，主会话直接跑——实测主会话连跑十几轮 SSH + 探针全程没撞，比派子代理更省也更快。必须引用订阅 URL / 密钥这类值时用 shell 变量传（`U=$(grep ...)` 再 `curl "$U"`），**不让它出现在输出里**。这类探针落成 skill 的 `scripts/*.py`，下次直接跑，别每次重拼命令。
- **长期做法**：高敏领域的原文（订阅正文、节点清单、代理配置全文）一律不进主上下文——要么由脱敏探针处理，要么交子代理，主会话只收结论。

## 结论怎么写

- 给**时间线证据**：哪条消息进来、几秒后首次 400、此前成功轮次不含该内容。不要只丢一句「可能是随机误判」。
- 同时说清这是**强相关不是因果证明**（审核黑盒、有非确定性），但时间线卡得够死就足以据此行动。
- 主人的关注点是「还能不能继续干活」，结论要落到**怎么绕、谁去干**，不是技术科普。
