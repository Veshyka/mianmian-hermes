# AutoBangumi + qBittorrent 实战排障记录（2026-08-25 首部署全记录）

飞牛 NAS 部署自动追番链路（AutoBangumi estrellaxd/auto_bangumi v3.3.5 + qBittorrentee superng6/qbittorrentee）的完整踩坑记录。compose 位于 `/vol2/docker/bangumi/compose.yaml`。

## 1. qB 临时密码（每次启动不同！）

- qB 首次/重启后日志生成**一次性临时密码**：`docker logs qb | grep -i password` → `临时密码：KZXnacdqc`
- ⚠️ **重启后密码会重置回临时密码**——用 API `setPreferences {"web_ui_password":\"<SECRET>\"}` 改密码后，**必须确认写入配置文件**（`grep -c "WebUI\\Password" /vol2/docker/bangumi/qb/qBittorrent/config/qBittorrent.conf` 应为 1）；qB 退出时用内存配置覆盖文件，运行中改文件会被冲掉——**停容器再改文件**。
- 判断当前密码：`curl -X POST http://127.0.0.1:8989/api/v2/auth/login -d "username=admin&password=\"<SECRET>\"` 返回空（失败）或 `Ok.`。

## 2. qB 代理配置（BT 走 mihomo）

**API 的 `proxy_type` 字段经常不生效**（preferences 里显示 None）——直接改配置文件最稳：
```bash
docker stop qb
sed -i 's/Proxy\\Type=None/Proxy\\Type=HTTP/' /vol2/docker/bangumi/qb/qBittorrent/config/qBittorrent.conf
docker start qb
```
- mihomo 17890 是 **HTTP 代理**——`Proxy\Type=HTTP`（不是 SOCKS5！qB 枚举：None/SOCKS4/SOCKS5/HTTP/HTTPConnect）
- IP/Port 用 `172.17.0.1:17890`（docker0 网关视角；qB 容器内 127.0.0.1 是它自己）
- `Proxy\Profiles\BitTorrent=true` + `Session\ProxyPeerConnections=true` 确认 BT 流量走代理

## 3. 「找不到种子」排障

- **根因链**：Mikan 种子 tracker（tracker.mikanime.tv/tr.mikanime.tv）**国内直连被墙**；走代理时**部分机场节点禁 BT**（tracker 返回 502——全节点测都 502 = 机场策略，不是配置问题）
- **判断**：`curl -x http://127.0.0.1:17890 -o /dev/null -w "%{http_code}" "http://tracker.mikanime.tv:6969/announce"`——502 = 节点禁 BT；对比公共 tracker `tracker.opentrackr.org:1337`（400 = 通，缺参数正常）
- **结果**：qB 配好代理后 Mikan 种子实际能下（AB 抓 RSS 拿种子 → qB 下载跑起来，进度正常涨）——代理配置是关键
- mihomo 日志确认流量走向：`docker logs mihomo | grep tracker` → `match Match using 节点选择[...]`

## 4. AB 连不上 qB（Auth failed / Cannot connect）

- AB 容器访问 qB 用 **`qb:8989`**（compose 网络容器名，IP 会变）
- AB 报 `Cannot connect` + 配置 get 显示 host 回默认 `172.17.0.1:8080` = **配置被重置**（见 SKILL.md 持久化节——改挂载 config.json + 重启）
- 修完配置后**重启 ab 容器**让连接器生效（API check 可能 true 但连接器缓存旧值）

## 5. 添加订阅的坑

- `POST /api/v1/rss/subscribe` 需要 `data`(Bangumi) + `rss`(RSSItem) 两对象；**Bangumi 的 `rss_link` 字段必须有**（缺失 → AB 日志 `UnsupportedProtocol / Unable to connect to ` 空 URL 错误 + 下载失败）
- 订阅加成功后：`GET /api/v1/bangumi/get/all` 验证；下载任务出现在 qB（`/api/v2/torrents/info`）
- AB 定时抓取默认 900s——测试可临时改 config.json `program.rss_time=60`（改完重启；测完改回 900）

## 6. mihomo 节点切换排障（机场节点批量被封）

- **症状**：所有走代理流量 000/超时；mihomo 日志 `connect error: connection reset by peer`（RST = 节点被封，不是网络不通）
- **测节点**：`curl "http://172.22.0.3:9090/proxies/<urlencoded节点名>/delay?timeout=4000&url=https://cp.cloudflare.com/"`——503/504 = 挂；返回 delay = 活
- **规律**：中转/IEPL 类节点全挂时，「直连」类节点往往活着（日本原生-直连 550ms / 台湾-直连 / 香港家宽-直连）
- **切换**（mihomo API 在容器 IP 172.22.0.3:9090，宿主可访问；用 python PUT 避免 emoji 节点名 shell 编码坑）：
```python
import json, urllib.request, urllib.parse
base = "http://172.22.0.3:9090"
group = urllib.parse.quote("节点选择")
data = json.dumps({"name": "🇯🇵|日本原生-直连"}).encode()
req = urllib.request.Request(base + "/proxies/" + group, data=data, method="PUT", headers={"Content-Type": "application/json"})
urllib.request.urlopen(req, timeout=8)
```
- 无 secret（external-controller 0.0.0.0:9090 未配 secret）
- 配置硬编码节点（无 proxy-providers/订阅 URL）——机场更新后需手动换配置
