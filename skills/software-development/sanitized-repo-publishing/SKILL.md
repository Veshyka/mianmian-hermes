# 把私有工作区脱敏后发布出去

用在：主人说「把这些东西传到 GitHub / 分享出去 / 给别人看 / 做个云端副本」——对象是自己的工作目录、
自建服务的定制件、脚本、笔记、技能包。核心不是 `git push`，是**上传之前的取舍与验证**：
必走「白名单拷贝 → 脱敏 → 独立复核」三闸，全过才谈上传。

本机现成工具（留在 `/opt/data/scripts/`，跨会话可用）：

| 脚本 | 作用 |
|---|---|
| `publish_prepare.py` | 白名单拷贝 + 脱敏 + 自带复核扫描 → 产物 `publish/repo` |
| `publish_verify.py` | **独立**复核：从源头读真实凭证值，在产物树里搜 |
| `publish/overlay/` | 手写的仓库门面（README / SECURITY.md / .gitignore / LICENSE），每次生成时覆盖进产物 |
| `publish_push.sh` | 一条命令跑两道闸 → 提交 → 推送；`publish_push.sh --check` 只跑闸不推（公开前复核用） |

## 开跑前先查三件（决定可行性与走法）

```sh
git --version; gh --version 2>/dev/null || echo "gh 没装"      # 没装 gh 不影响：纯 git 够用
ls ~/.git-credentials ~/.config/gh/hosts.yml 2>/dev/null      # 有没有现成登录
curl -s -o /dev/null -w '%{http_code}' -m 6 https://github.com # 通不通（本机实测直连 200）
```

认证没配就**先回答「没登录」**，把决策摆给主人（SSH key 推荐：私钥留本机、不进仓库；或 PAT）。
不要自己猜账号、也不要暗示「已经能推了」。

## 铁律（每次都要遵守）

1. **白名单，不是黑名单。** 只拷显式列出的路径。「除了敏感的其余都传」一定漏——数据目录里
   散落的凭证（旧交接目录、协议端配置、askpass 脚本、secrets/、状态文件、日志）永远比想象的散。
2. **先本地建产物，同一个目录里不手写文件。** 生成器每次会重建产物目录 → 手写的 README/许可证
   放 `overlay/`，由脚本拷进去；否则一跑就被删。**重建时只清内容、保留产物根下的 `.git`**——
   连 `.git` 一起删，等于每发一次就把提交历史清空，之后只能强推。
3. **两道闸都过才谈上传。** 生成器自己的「✅ 干净」不算证据；必须有独立复核（见下）。
4. **先私有仓，扫干净再转公开。** 推上去的一瞬间就可能被抓走，历史删不干净。
5. **按主人的排除规则剔**：凭证 / 记忆 / 人设（含提示词、聊天风格偏好、规则文件维护方法）/
   第三方数据（群友号码、群聊正文、别人的媒体文件）/ 主人私事（个人资料、学业决策类笔记）。
6. **别把「不是完整灾备」说成「云端备份」。** 排掉记忆/人设/凭证之后，能上云的恰恰是**可再生**的那部分；
   先把边界说清，再谈好处（可读、可复用、代码与文档的异地副本）。
7. **汇报要给数**：产物目录、文件数、字节数、跳过数（+原因）、脱敏替换计数、主动剔除清单、待决策项。
8. **别人的东西不冒充成我们的。** 技能/代码目录里混着上游自带与第三方安装件，选材时逐条判：
   与 Hermes 自带目录**逐字节相同** → 上游的；`SKILL.md` 的 `author:` 不是本地/本方 → 第三方的；
   通篇找不到任何本机标记（本机路径、协议端名、部署专名）→ 通用模板。三类都不进仓库。
   实测一轮就剔掉 121 个文件，留下的才是真正的本地定制。
9. **推送成功 ≠ 远端内容对。** 收尾必须**从远端读回来核**，三样都要：① `git ls-remote origin`
   对 commit；② 拉远端文件树（API 或 `git ls-tree`）看文件数、看有没有敏感路径；③ 抽 1~3 个
   文件把**内容**下载回来验脱敏与占位符。只验本地等于没验。转公开后**再匿名（不带任何凭证）**
   打一次仓库页与 raw 文件，200 才算真的公开。

## 步骤

1. **侦察规模与污染面**：`du -sh --exclude=.venv */` 看谁大；用一轮粗扫估敏感面
   （`grep -rlIE "Bearer [A-Za-z0-9._-]{8,}|sk-[A-Za-z0-9]{16,}|api[_-]?key|passwd"`，排除 cache/logs）。
   大目录（GB 级模型、缓存、媒体）根本不进仓库，别把它们列进白名单。
2. **写白名单**：一条条列路径（树或单文件），并在注释里写**为什么剔掉邻居**（`research/` 里有私事数据、
   `communication/` 里有个带人设的文件）。技能类目录要逐个挑，不要整类搬。
3. **硬排除（哪怕在白名单树里）**：`memories/ logs/ secrets/ .env* *.db* *.token` 与 askpass 脚本、
   状态/游标文件（`*-state.json`、`*-proactive.json`、`*-backfill.json`）、`cron/jobs.json`、
   **`*.bak-*` / `*.orig` / `*~` 备份文件**（会夹带旧版本里的明文）、二进制与媒体扩展名。
4. **脱敏一遍（静态规则）**：号码/token/key/订阅链接/真名昵称/本机仓库路径 → 占位符，
   占位符集合要统一且可搜（`<OWNER_QQ> <BOT_QQ> <GROUP_ID> <TOKEN> <SECRET> <SUBSCRIPTION_URL> <OWNER> /vol1/1000/<USER>`）。
   规则目录与坑见 `references/sanitizer-rule-catalogue.md`。
5. **脱敏二遍（动态真值）**：从源头读出**真实**凭证值（协议端配置里的 token、askpass 脚本里的口令、
   `secrets/` 下的 token、各 `config.yaml` 的 key），在文本里替换成 `<SECRET>`。
   静态正则列不全「漂到文档/技能里的真 key」，这一步兜住。跳过明显占位值（`not-needed`、`placeholder`、`***`）。
6. **复核扫描**：对产物再扫一遍禁用模式（见 references）。命中数**必须归零**才继续。
7. **独立复核**：跑 `publish_verify.py`（或等价物）——它自己从源头读真值再搜产物，不读上一步的结论。
8. **落门面**：README（这是什么、目录表、怎么跑两道闸、已知边界）、SECURITY.md（不上传什么、脱敏方式、
   发现泄漏怎么办）、.gitignore（纵深防御：`.env*`、`*.token`、`*.db`、`*.bak-*`…）。
9. **给主人看清单 + 待决策项**（公开策略 / 认证方式 / 许可证），**等他放行再建仓推送**。

## 坑（都踩过）

- **号码别用 `\b` 边界**：`\b1[0-9]{8,10}\b` 抓不到夹在更长数字串里的目标号码，用 `(?<!\d)N(?!\d)`。
  实测：换成 lookaround 后同一文件里多抓出 3 处漏掉的机器人号码。
- **订阅正则要要求 URL scheme**：宽松的 `sub|subscribe|clash|token=` 会把 `subprocess.CompletedProcess`
  这种普通代码判成泄漏。写成 `(?:https?|vless|vmess|trojan|ss|...)://...[token=|sub|clash|v2ray]...`。
- **`sk-` 规则要区分真假**：真密钥够长（`sk-[A-Za-z0-9]{20,}`）且可能被文档写成截断形态
  （`sk-<KEY>`，注意可能是 unicode 省略号 `…` 而不是 `...`）；门限太松会把路径片段
  （`sk-cleanup`、`sk-workflow`、`SK-BRIEF.md`）全判成密钥，把闸淹在误报里。
- **路径黑名单别写宽词**：把 `hindsight`（开源记忆引擎名）当禁词会把自己写的插件目录全判违规；
  禁词要具体到数据目录（`/hindsight/`、`state.db`、`secrets/`）。
- **误报要显式留白名单，不要放宽规则**：把核实过的值（`message_id`、epoch 时间戳、测试夹具、`1 GiB` 内存上限）
  写进 `BENIGN_NUMBERS` 并附一句为什么——这样**任何新出现的值照样会被扫出来**，逼人看一眼。放宽正则等于把闸拆了。
- **复核必须是两套独立实现**：本机首轮扫描 54 处可疑 → 收紧误报后 35 处 → 加动态真值才 0 处。
  只跑生成器自带的扫描，第一版就「通过」了。
- **生成器重建的是自己的输出目录**：删之前确认路径是产物根（源目录一个字节都不碰）；
  白名单里有不存在的路径要**报错**而不是静默跳过——少拷比多拷安全，但悄悄少拷会让主人以为东西都在。
- **一个脚本改多个文件时，每个文件用独立变量名**：共用变量会把一个文件的内容写进另一个文件
  （本机真的发生过：一个文件被整篇覆盖）。
- **产物根下的 `.git` 要从扫描里排除**：reflog / COMMIT_EDITMSG 里的 epoch 时间戳会被「疑似号码」规则
  当成泄漏，报出假阳性；拷贝、复核扫描、独立复核三处都要跳过 `/.git/`。
- **别为了一件事去装新工具**：本机 `git` + SSH 就够推仓库，缺的 CLI（如 `gh`）不是必需；
  真下载二进制就**先核对 release 的 sha256 再 install**——半截下载（网络中断/超时）会留下坏文件，
  只有校验能发现（实测下到的 11 MB 包只有 1.1 MB，校验对不上就该拒绝安装，不要「装完试试看」）。
- **shell 里别用 `if cmd | tail; then` 判成败**：管道状态码取最后一个命令（`tail`），永远为真。
  写成 `if out=$(cmd 2>&1); then ... else echo "$out"` —— 尤其别让发布脚本把失败报成「已推送」。
- **排除规则要同时管「目录名」和「文件名」**：只挡 `prompts/ chat-profile/ backup/` 这类目录，
  散落在树根的 `*persona*`、`*persona-prompt.md` 照样会漏进去（实测一次漏了 4 个）。文件名通配与
  目录名通配各写一遍；`.bak-*` 这类**目录**要按前缀挡（`d.startswith(".bak")`），别只写在文件通配里。
- **`.gitignore` 的 `secrets/` 不覆盖 `.secrets/`**：点号不同名就是两条不同路径。凭证目录一旦带点，
  必须单独写一行，再补 `*credential*`、`*_token`、`.ssh/`、`.config/` 做纵深防御。
  （另一层硬隔离：仓库根是**产物子目录**、源工作目录根本不是 git 仓库，凭证文件物理上不在任何仓库范围内。）
- **写凭证前先确认目标目录可写，并让脚本写失败时硬报错**：`secrets/` 这类目录常是 root 所有（`700`），
  普通用户写不进去；而「先写文件、后打印成功」的脚本会把 permission denied 吞掉，报出
  `LOGIN_OK token 已写入` 这种假成功（代价是要主人白授权一次）。写到自己的可写目录（如 `~/.secrets/`），
  写盘失败当致命错误退出。
- **本地专有技能会被「通用模板」过滤误杀**：某技能确实是自己写的、但正文里没有本机标记，就被当成
  通用模板剔掉了。给这类文件留一个显式 `SKILL_ALLOW`（写**相对仓库根的真实路径**——技能可能嵌在
  类别目录下，也可能在 `shared-skills/` 这类平级目录里），比放宽整体过滤安全。
- **白名单里写不存在的路径要报错，不要静默跳过**：静默跳过会让「以为收进去了」骗过自己和主人
  （实测一次把技能白名单写成错的目录层级，跑出来的产物少了整套文件却没人发现）。
- **别在命令里拼 `A="-x $PX -H Authorization: token $TOK"` 这种变量**：word-splitting 会把
  header 拆成两个参数、把 token 当成 URL，静默变成 401/502 假失败。header 要原样写在命令行里。
- **跑闸/推送别用长前台超时**：后台会话一次发布要几分钟，前台超时设成 >600s 会被**静默转成后台**，
  当轮拿不到结果、还得等一次通知才接得上。要当场看结果就把超时压到 ≤540s（闸通常 1~2 分钟，够），
  确实要更久就主动用后台 + 完成通知，并把后续步骤（转公开、发链接）写成「通知到了再接」。

## 授权与节奏

主人对这类「优化性质」的改动授权往往很宽（「你要改就改」），但**推送**这一步永远等他明确放行：
先给产物清单 + 待决策项，得到答复再动远端。中途发现真泄漏（真 key 落在技能/文档里）要**单独点出来**，
并顺手把源头也修掉（不是只修产物）。

## 日常节奏：改完就传（主人的长期要求）

主人把这件事定位成**例行备份点**（「弄完了就传上去，每一次改完之后就相当于备份了一次」），
所以链路跑通后不要再人工重复拼命令：

```sh
scripts/publish_push.sh "这次改了什么"   # 跑闸 → 提交 → 推送（闸不过就地中止，绝不推）
scripts/publish_push.sh --check          # 只跑闸：公开前/推送前的复核
```

* 提交说明带时间戳即可，别为了「好看的提交历史」去整理产物（产物是机器生成的）。
* 产物和上次逐字节相同 → 不提交、不推送，打印一句就退（避免空提交刷屏）。
* 本地提交成功但推送失败时**不要回滚提交**：留着，修好网络/权限重跑同一条命令即可。

## 认证与开仓：让主人只做两步

主人挑认证方式的标准是「哪个方便我用哪个」，所以选**用户手动动作最少**的路：

1. 生成 SSH key 放进**持久挂载目录**（如 `/opt/data/.ssh/`，重建不丢），并把私钥排除在发布白名单外；
2. 验证连通性：`ssh -i <key> -T git@github.com` → 回 `Permission denied (publickey)` 就是**通了**
   （只是公钥还没加），别把它当失败；
3. 把**公钥那一行**发给主人贴（Settings → SSH and GPG keys）——只让主人交公钥，任何需要把
   口令/token 打出来的方案都不要用（凭证不进对话）；
4. 让主人在网页建**空的私有仓**：不勾 README / .gitignore / LICENSE（勾了会和推送内容打架，多一次合并）；
5. 拿到仓库地址后 `git remote add origin git@github.com:<用户>/<仓库>.git`，跑一次 `publish_push.sh`。

主人想「全自动、别让我点建仓」时走**设备码**（他自己只需在浏览器确认一次）：
`POST /login/device/code`（**显式挂代理** + 带 `User-Agent`）拿到 `user_code`/`device_code` →
把 8 位码和 `https://github.com/login/device` 发给主人（提前说一句「页面显示授权给 GitHub CLI 是正常的」，
免得他犹豫）→ 后台轮询 `POST /login/oauth/access_token` 直到拿到 token → token 落盘到**可写目录**
（600、不进白名单）→ `POST /user/repos {"name":"…","private":true}` 建私有空仓。
推送仍走 SSH，token 只用于 API。命令与轮询脚本写法见 `references/github-auth-and-remote-verify.md`。

## 网络：代理必须显式给，否则是「能 GET、不能 POST」的假象

沙箱/容器里常常**没有** `http_proxy` 环境变量（`env | grep -i proxy` 为空），于是同一台机器上会出现：

| 动作 | 直连 | 显式挂本机代理（`-x http://<宿主>:17890`） |
|---|---|---|
| `GET https://github.com` / `api.github.com` | ✅ 200 | ✅ 200 |
| `POST https://github.com/login/device/code` | ❌ 卡到超时（连响应头都没） | ✅ 秒回 200 |
| release 包（`gh` 之类二进制）下载 | ❌ 中途断流、sha256 对不上 | ✅ |

**规则**：`curl` 一律显式 `-x <本机代理>`（端口要真测：`bash -c "echo > /dev/tcp/<宿主>/<port>"`），
不要指望环境变量。遇到「GET 通、POST/下载卡死」先查这条，别怀疑账号或权限；`ssh -T git@github.com`
仍然是验证推送通道最快的办法（SSH 走 22 端口，与这里的 HTTP 路径无关）。
下载二进制**先挂代理再下**，并在 install 前核对 release 的 sha256。

**建仓不能靠 push**：往不存在的仓库推，GitHub 回 `ERROR: Repository not found`——没有 push-to-create。
建仓只有两条路：让主人网页点，或用 API token 打 `POST /user/repos`。两条都要**先私有**。
