# 宿主 docker / 容器运维事实（2026-09-18 实测）

## 拿 docker 权限

宿主用户 `棉棉`(1003) **不在 docker 组**，要用 sudo：

```sh
export SUDO_ASKPASS=/vol1/1000/<USER>
sudo -A docker ps
```

## 镜像源

- `ghcr.io` 直连 + 走代理都 TLS 失败（`Get "https://ghcr.io/v2/": EOF`）
- → 用 `ghcr.nju.edu.cn`（内容同源，digest 可对）

## GPU 直通（重要更正）

`docker info` 里已经列出 CDI 设备：

```
cdi: nvidia.com/gpu=0
cdi: nvidia.com/gpu=all
```

直接用 `--device nvidia.com/gpu=all` 即可。**不需要改 `daemon.json` 加 nvidia runtime，也不需要重启 docker**
（重启 docker 会把 Hermes 容器一起带下去）。旧结论「必须先加 runtime」作废。

## 飞牛应用中心

- 应用名 `ai_installer` = Ollama + WebUI；启停一律走 trim-cli
- 崩溃常见原因：残留实例抢端口 → 别用宽泛的 pkill（会杀掉自己那条 SSH），先 `pgrep` 拿 PID 再杀
- `fygo-browser` 不支持生命周期接口（restart 10350 / start·stop 10500）→ 见 skill `fygo-browser-use`

## 其他宿主事实

- `daemon.json`：data-root `/vol2/docker`、live-restore 开、代理 `127.0.0.1:17890`、多个 registry-mirrors
- ⚠️ `docker stop hermes` 会把自己停掉 → 重建容器必须用宿主 nohup 后台脚本方式

## 路径约定

**主人说「和你映射到一个文件夹」= `/vol1/1000/<USER>`**（就是容器里的 `/opt/data`，两边看到同一个目录）。
新生出的服务/数据按这个约定放，例：`llamacpp/{models,logs,tmp}`。
