# AstrBot 时代技术坑（已退役，但仍值得留档）

> 2026-09-23 起该框架已 `docker stop`（容器保留、可随时开）。下面这些坑多数是**通用**的：换任何容器内改源码/改人格库的框架都会再遇见。

## 1. 人格白名单挡不住框架每轮硬性的工具注入 → 必须每轮剪枝

**事实**：框架的 local runtime 在 `astr_main_agent.py` 的 `_apply_local_env_tools()` 里**每轮无条件**往请求里塞 shell / python / shell_session / 文件类工具，**还往 `system_prompt` 加一段英文「你能跑 shell 和 Python」**。`persona.tools` 白名单**挡不住**它们。

**正确做法（两层）**：
1. 人格白名单（`personas.tools`）改显式闭集；
2. 插件在 `@filter.on_llm_request()` 里按白名单**逐个 `remove_tool()`** —— 每轮都剪，不能只剪一次。

**那段英文提示也要治**，而且**必须逐句校正**，不能整段删也不能整段留（删了里面对的有用句，留了就以为自己能跑 shell）：删 shell/python 句、留 workspace 相对路径句。**改动依据是「本轮真实白名单」，不是静态列表。**

**验证**：启动日志的「白名单稽核」行 + 每轮的「边界执行」行（应出现「本轮摘掉 N 个白名单外工具」）+ 走**真身**（真装饰器/真事件/真 handler）的自测。

## 2. 白名单字段的语义坑：`None` 与 `[]` 不是一个意思

- `persona.tools = null` → **全量工具**（默认值！）；
- `persona.tools = []` → **一个不给**。
- 填错的症状是模型自称「够不着 / 没权限」，不是报错。
- **新增插件工具必须同步加进白名单**并重跑写库脚本，否则她够不着，只有一行日志。

## 3. 分段（多气泡）是通道层的活

- 切分/清理**两个配置必须配套**：只加 `content_cleanup_rule` 不加切分字符类 = 永远不切；符号不算进切分字符类也不会被清。
- **阈值是上界不是下界**：整条超过阈值（本机 150 字）→ **整段发、不切**（反直觉）。
- **换行不是切分符**（实测三行无标点 → 只发一条）；语气词收尾不切。
- **分隔符选择**：文档正文里会出现的符号（如 `※`，引用注记常用）不能当分隔符 → 换成 `⁂`(U+2042)；容错集合 `⁂`/`※`/`⸮` 全留着（模型沿用旧话术也照样切且不会发出去）。
- **明确否掉**：不要把换行符加进切分正则（等于纵容拿换行代替标点）。

## 4. 容器内源码补丁会被升级/重建吃掉 → 要么登记+自愈，要么别打

- 代码在 `/AstrBot`（**不在卷里**）→ 重建后补丁消失，但**配置在 `data/`（卷）不丢**。两者要分开对待。
- 本机制：补丁载荷放挂载目录 + compose `entrypoint` 先幂等重打再自检再 `exec` 原 CMD（重建自愈）+ 宿主 `apply-from-host.sh` 一键兜底 + `patches-boot.log` 落盘留痕。
- **补丁会自愈，插件依赖不会**：插件 pip 依赖装在容器可写层，重建后启动时**串行重装**，期间平台适配器没起 → 聊天链路整段不可用（实测卡死 10 分钟）。处置：把出问题的插件 `mv` 到 `plugins_disabled/` → 重启；依赖装完再 `mv` 回。换国内源能快一个量级。
- 不用 patch 的那部分（人格/参数/白名单）住在 `data/` 卷 → **重建不丢，但换机器/换卷要照登记重做**。

## 5. 其他（同批）

- 人格提示词里的段落正本要入库（插件目录），**别手改库里那份**——写库脚本会按段落整段替换，手改一下次就没了。
- 停用/替换插件时注意目录里有挂载点时不能直接删，要改 compose（见 `astrbot-platform-ops.md` §六）。
- 面板口令只存哈希（只能重置）；凭证交付不进聊天正文（见 `astrbot-platform-ops.md` §一/§二）。
