# 本地 VLM 能不能当「看图后端」：测量方法 + 判定结论

触发场景：要决定「把 `auxiliary.vision` 指向本地 VLM」值不值，或评估任何本地/云端 VLM 的识图质量。
**只报一个总分（甚至只报「识别正常」）不足以决策**——必须回答「错在哪、错了会不会被下游发现」。

## 一、量尺先行（选材料，不选好看的）

从**本机真实材料**造 ≥6 类样本，每类必须有可比对的 ground truth（PDF 文本层最好，没有就手写）：

| 场景 | 取材 | 为什么要它 |
|---|---|---|
| 中文正文 150dpi | 学术/公文 PDF 抽页渲染 | 最有利场景，给模型公平机会 |
| 中文正文 72dpi 或缩图 | 同页降 dpi | 模拟小字扫描/聊天截图，看崩塌阈值 |
| 数字密集表（投档线/名单） | 考试院类 PDF | 数字 + 中文混排，最容易编造 |
| 含公式/数字段落 | 论文 PDF | 符号与单位 |
| 中英混排公文（正文+表） | 合成 HTML→PNG，GT 自己写死 | 干净渲染下的上限 |
| UI 截图（中英+数字+时间戳） | PIL 合成，GT 手写 | Hermes 实际最常见的输入（界面截图/报错页） |

渲染：`pymupdf`（`import pymupdf`，别用 `fitz` 旧别名），`page.get_pixmap(dpi=150).save(png)`；GT = `page.get_text()`。
合成图用 PIL 直接画，GT 同时写进 JSON——比找真截图省事且可比对。

## 二、问两遍：整页转录 + 定向提问

1. **整页转录**：「请逐字转录图中的全部文字，保持阅读顺序，不要翻译、不要总结、不要加任何解释。」
2. **定向提问**（表格/截图类必须加）：问具体字段（某行的每个单元格、设备路径、时间戳）。
   **表格幻觉往往只在定向提问时才暴露**：整页转录时它会把表头猜对、行数据抄错，定向提问则直接退化成编造 + 重复循环。

## 三、打分：三个数，缺一不可

- **CER**（字符级错误率）：`difflib.SequenceMatcher` 的 opcodes 累加 `insert/delete/replace` 的 `max(len_gt,len_out)` ÷ GT 字数。直接跑 `scripts/vlm_page_bench.py`。
- **数字 token 命中率**：`Counter(re.findall(r'\d+', ...))` 求交集 ÷ GT 数字数。**CER 好看但数字命中率低 = 不可用于任何要读数的场景**。
- **同题 A/B**：同一张图、同一个问题，跑一次主模型视觉（`vision_analyze`）。**没有这个对照就没有决策依据**——本地 1B 的绝对分再高也可能不如现成路径。

打分前**先剥掉模型擅自加的标记**：它会用 `<table><tr><td>` 包表格，把裸 CER 抬高一倍多（实测 54.5% → 9.2%）。`re.sub(r'</?t[d|r]?>|</>', '', out)`。

## 三点五、思考开关：per-request 就能关，别去改 compose（实测）

`minicpm-v4.6` 系思考模型的 `reasoning_content` 会先吃掉 `max_tokens`：给 800 时整页转录常 `finish_reason=length` + `content` 为空，**看着像坏了**（这是最大的假故障源）。

**在请求体里加这一行就能关掉思考，不需要 `--jinja`、不需要重建容器：**

```json
{"model":"minicpm-v4.6:1b","max_tokens":4096,"temperature":0.1,
 "chat_template_kwargs":{"enable_thinking":false},
 "messages":[...]}
```

实测（build b11028，同一实例、同一图，max_tokens=4096）：

| 场景 | think 关 | think 开 |
|---|---|---|
| 纯中文正文 150dpi | 21.2s / 782 tok / CER≈2% | 33.1s / 1687 tok / 3.5% |
| 投档线数字表 | 18.0s，**48/48 行全出**，单元格数字 148/165=89.7% | 18.0s，4096 tok 全被 reasoning 吃掉、输出截断 |
| 72dpi 小字页 | 7.0s | 9.9s |
| UI 截图定向问答 | 1.0–2.9s | 2.8–6.0s |

结论：关思考**不掉质量、快 30–40%、且避免截断**，应当作为默认调用方式。容器级 `--reasoning off` 唯一好处是不用改调用方，但代价是重建容器 + 影响所有调用方 → 不值得。

**调用方硬规则**：`max_tokens >= 4096`（关思考时 2048 起）——整页 A4 转录一次要吃 2000–4000 token。

## 四、实测结论（12G 卡 llama.cpp / minicpm-v4.6-1b / Q4_K_M）

| 场景 | GT 字数 | CER | 准确率 | 耗时 |
|---|---|---|---|---|
| 中文正文 150dpi | 1257 | 3.5% | 96.5% | 33s |
| 中文论文含公式段 | 1237 | 7.8% | 92.2% | 27s |
| 合成公文（正文+表，去标签后） | 424 | 9.2% | 90.8% | 8s |
| 正文缩到 72dpi | 1316 | 40.2% | 59.8% | 13s |
| 高考投档线表 150dpi | 1794 | 62.8% | 37.2% | 59s |
| UI 截图（中英+数字） | 236 | 30.5% | 69.5% | 6s |

投档线表数字 token 命中率 234/341 = **68.6%**（该数字用 Counter 求交集，**偏宽松**：同一数字出现错行/错单元格也算命中，别拿它当决策依据，看单元格对齐后的数字准确率）。同题 A/B：主模型视觉在这两类图上逐行读对，与 PDF 文本层一字不差。

**2026-09-19 复测（关思考，同图同模型）**：数字 token 命中率升到 312/341 = 91.5%，按「院校代号+专业代号」对齐后单元格数字精确匹配 148/165 = **89.7%**，48/48 行全出；但院校名精确 23/33（70%）、专业名 16/33（48%）——**行归属和名称仍不可信**（`北京中医药大学`→`北京中医中医药大学`、`北京第二外国语学院`→`北京第一外国语学院`）。

## 五、失败模式（可跨模型复用为验收项）

1. **平滑错值**——最危险：`123 GB`→`132 GB`、`/dev/nvme1n1`→`devmne1`、`2026-09-19 03:14:22`→`2028-09-10 19:03:14 22`、`fnOS`→`fnO3`。读起来像对的，**下游无法自检**。凡是要读数字/时间戳/路径/人名的场景，错值 = 不可用，不看 CER。
2. **人名与专名乱写**：`徐祥云`→`祥云祥`、`方光宝`→`万光宝`、`刘福才`→`周树才`、`北京中医药大学`→`北京中医中医药大学`、`(梁希实验班)`→`(实验室班)`（后者是**编造**，不是识别错）。
3. **整段编造**：`置教育改革于不尴不尬之地` → `教育改革于不触于难也之`。
4. **表格退化重复**：定向提问下把某一列的值（如 `72`）连刷几百次直到 `max_tokens` 截断。看到重复循环立刻判不合格，不要调参数再试。
5. **丢单元格**：`600 | 212 | 113` → `600 | 113`——错位比错值更隐蔽，单元格计数对不上就是不可用。
6. **小字崩塌**：72dpi 下输出仍是「像中文的胡话」，CER 40% 只是表象，实际是成句编造。

## 六、判定规则

- **要让本地 VLM 当 `auxiliary.vision` 后端，它必须在「数字密集表」和「UI 截图」两类上不掉链子**；这两类达不到主模型视觉水平，就不要动配置。`hermes-image-routing.md` 里那条「这条路是有损的」不是理论风险，是 30-63% 字符错。
- 本地小 VLM 的现实用途只剩**离网/断 API 时的整页粗读兜底**——用它就得接受「只取大意、绝不引用具体数字」。
- 结论可直接搬：**12G 卡上的 1B 级 VLM 不接成归默认看图后端**（主模型视觉更好且更快）。换更大本地 VLM 要重跑本流程，别外推。

## 七、跑测量脚本时的坑

- **别把脚本命名成 `inspect.py` / `json.py` / `types.py` 放在工作目录**：cwd 参与模块搜索，`import inspect` 会命中自己的脚本，第三方库（pymupdf 等）在 import 期就炸（`AttributeError: module 'inspect' has no attribute 'signature'`），报错指向库里，非常难查。
- **runner 模块里不要读 module 级就把请求跑全**：`from runner import ask` 会重跑整批任务。用 `if __name__ == "__main__":` 包住批处理，或把 `ask()` 单独放 `vlm_client.py`。
- **长批量走后台进程，别用前台超时**：一张 150dpi A4 页要 6-60s，十几张就过 600s 上限，会被自动转后台（然后 `| tail` 把输出吞掉、进度看不见）——把结果逐条 append 写 JSON，再读回来聚合。
