# 局域网二层只读体检（独立观测点 = NAS / 容器）

主人说「某台设备持续丢包 / 上了旁路由就全网不稳 / 是不是二层被污染」时用本流程。
**先体检、后改配置**；全程只读，不碰任何设备的配置、不发 DHCP DISCOVER。

## 观测点选择
- 优先 **NAS 宿主**（真在 192.168.1.0/24 上，能发 ARP/ICMP）。
- 容器内**通常没有 `CAP_NET_RAW`**：`ping` 直接 `Operation not permitted`，raw socket 全废 → 容器只用来发起 SSH，所有主动探测在宿主跑。
  `SSH_ASKPASS=/opt/data/scripts/askpass.sh SSH_ASKPASS_REQUIRE=force ssh 棉棉@172.17.0.1`，宿主侧 `export SUDO_ASKPASS=/vol1/1000/<USER> sudo -A …`。
- 要跑脚本：`ssh … 'cat > /tmp/x.py' < local.py` 推上去，再 `ssh … 'bash -s' < local.sh` 执行；`sudo -A python3 - <mode> … < local.py` 可直接 stdin 喂脚本。

## 分层判定顺序（按序，别跳）
1. **端口计数器**：`ip -s link show <iface>` 间隔 ≥30s 取两次。errors/carrier/collsns=0 且 RX dropped 不增长 → 观测口自身无 L2 错，后面的推断才站得住。
2. **低速率 ICMP**：`ping -c 200 -i 0.2` 打网关与疑点主机，期望 0% 丢。
3. **高速率对照**：`ping -c 1000 -i 0.01` 打网关；**同时以同速率 ping 一个被转发的目的**（223.5.5.5 / 8.8.8.8）。
   这一步把「网关控制面限速」和「真 L2 丢包」分开（判读见下表）。
4. **广播/组播画像**（`l2_probe.py bcast`）：占比多少、来源是谁、有没有 <100ms 周期的重复帧、有没有非标准 ethertype。
5. **IPv6 RA 嗅探**（`l2_probe.py ra`，窗口 ≥300s）：数**不同源**、读字段（见下）。
6. **ARP 冲突体检**（`l2_probe.py arp` + 受控试验）——真凶通常在这一步。
7. **设备身份归属**：OUI + HTTP title + SSH banner。

## 判定表
| 观测 | 结论 | 处置 |
|---|---|---|
| 低速率 0% 丢；高速率大量丢；**但同速率 ping 被转发的目的 0% 丢** | 网关控制面 ICMP 限速（家庭光猫常见 ~10 pps 封顶，**与包大小无关**） | 不是 L2 故障；改用 TCP/UDP 复测 |
| 广播+组播占比 1~2%，无 <100ms 周期帧 | 无风暴 | 排除「被广播打爆」这条线 |
| 每秒 1 帧、非标准 ethertype（如 `0xfffa`）、来自光猫 MAC 变体 | ONU/光猫私有链路信标 | 带宽可忽略；不是旁路由干的 |
| 同一 IP 被 ≥2 个 MAC 应答 | **IP/ARP 冲突**（真凶） | 见「强制邻居缓存受控试验」 |
| 多个 RA 源，但其中一个 Router Lifetime=0 | 双 RA 存在，**不产生冲突默认网关** | 优先级低，副作用只是多余前缀下发 |
| 端口 errors=0 / dropped 不增长 | 观测口无 L2 错 | 别往链路层归因 |
| ARP 扫描 254 个地址几乎全 INCOMPLETE | 网段里设备很少（家庭常见 3~5 台） | 正常；别把扫描残留当「网关丢了」 |

## 强制邻居缓存受控试验（判定冲突的第二台设备到底转不转发）
原理：**单播 ARP 请求会定向刷新邻居缓存**，把缓存钉在指定 MAC 上，再立刻验证连通性。

1. 发**单播** ARP 请求（目的 MAC = A，target = 被抢的 IP）→ 缓存被写成 A。
2. **回读 `ip neigh show <IP>` 确认缓存真的等于 A**（必须！不校验会让 0% / 100% 两种结果随机出现，结论作废）。
3. `ping -c 10 -i 0.15 <IP>` 记丢包率；再回读一次缓存（看是否被对手的应答翻回）。
4. 换 MAC B 重复，两种各 5 轮。

判读：
- 缓存=A 0% 丢、缓存=B 100% 丢 → B 是**只回 ARP、不承载流量的黑洞**。用 `curl -m 4 http://<ip>/` 得 `000`、`busybox nc -w 3 <ip> 22 </dev/null` 无 banner 再确认一次。
- 广播解析命中黑洞的概率越高（实测约 **2/3**，35s 统计 19:10）→ 任何把该 IP 当网关/DNS 的客户端越会**成段全丢包**；这就是「持续丢包」的真身，而不是链路抖动。
- 两种缓存都 0% → 目前只是 ARP 抖动、尚未成灾，但仍是应清理的异常。

别误判成「ARP 欺骗」的三个反向判据：
- **只答广播、不抢答单播**（对 A 发单播询问时 B 不插话）→ 是「另一台设备确实占用了同一 IP」，不是嗅探投毒。
- **纯被动窗口内一次不发**（45s 内 0 帧）→ 没有免费 ARP 持续投毒。
- 60s 全量画像里它**只发 ARP**（`{0x0806: N}`，无 0x0800/0x86dd）→ 典型 IPv4-only ARP 应答器。

## IPv6「双 RA」判定（RA 字段解码）
被动抓 ICMPv6 type 134，读：
- **Router Lifetime**：`0` = 明确不把自己当默认路由（OpenWrt odhcpd 在上游无默认路由时会自动降级为 0）。只有**非 0 且与主路由冲突**才是「抢默认网关」。
- Flags/curhop：`M`(bit7) 管 DHCPv6 地址、`O`(bit6) 管「其他配置」。`curhop=0x40` = O 置位，正常旁路由行为。
- Prefix Information Option (type 3)：`L`(bit7) on-link、`A`(bit6) 自动配置；`A=1` 会给全网下发该前缀地址。Route Info Option 会带来更短前缀的 via 路由（如 /48 走旁路由）。
- **最可靠的判据是宿主路由表默认路由条数**，不是 RA 帧数：只有主路由一条 = 没产生冲突默认网关。
- 频率：默认 MaxRtrAdvInterval 600s，**每 5 分钟一个 RA 不是风暴**；窗口要 ≥300s 才可能抓到两个源。
- 邻居表里出现另一个前缀的 `FAILED` 条目，通常是 ISP 前缀轮换留下的陈旧项，**不要**据此断定有第三个在线路由器。

## 设备身份归属（只读）
1. OUI：`curl -s https://api.maclookup.app/v2/macs/<6位大写HEX>`（免 key）。返回 `"isRand":true` = 本地管理/随机化 MAC，查不到厂商。
2. HTTP 指纹：`curl -s -m 6 http://<ip>/ | grep -io '<title>[^<]*</title>'` —— 实测一眼分出「中国电信智能网关」(光猫) / LuCI(OpenWrt 旁路由) / 各厂商登录页。
3. SSH banner：`busybox nc -w 3 <ip> 22 </dev/null | head -1`（dropbear = OpenWrt 系）。
4. 边界：**连接尝试可以做，登录/改配置不行**；报告里写明做过连接尝试。

## 报告写法（主人要的形式）
- 写到指定文件；结论先行（一张「判据 → 实测 → 是否指向被告」的表），再放原始输出节选。
- 每个数字带**样本量与时间窗**（「305s 内 2 个 RA / 60362 帧」「800 包 0% 丢」）。单次测量不下结论。
- 「实测」与「推断」分节；末尾单列「未验证项」（例：两台冲突设备是否同交换机端口、第二台的真实身份、是否双 DHCP 服务器）。
- 明确回答主人真正问的那句（「是不是 X 在污染二层」），并区分「X 主动污染」与「X 的地址被别人抢答」。
