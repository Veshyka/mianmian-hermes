# 变更 2026-10-04：稳定性收口两件（主动起头名单只认真好友 + 干活门退出冲缓冲）

主人原话：「缓冲啥的你要加的话自己看着办，稳定性优先的考虑」+「顺便看看你那个随机找我聊天的功能效果如何」。

## 一、主动起头名单：只认真好友（修假会话白烧回合）

**症状（实测）**：

| 时间 | 发给了谁 | 后果 |
|---|---|---|
| 2026-10-04 15:00:28 | 群「<GROUP_NAME>」<GROUP_ID2> | `retcode=1200 无法获取用户信息` 连发失败 + 一条自检告警 |
| 2026-10-04 18:18:31 | **单测假会话 `123456`** | 白烧一个模型回合（22 字回复）+ 连发 1200 失败 + 重试风暴 |

`123456` 是单测夹具里的假用户，被写进了**真** `onebot-proactive.json`；`<GROUP_ID2>` 是群，
因为 `group_ids` 靠"收到群消息才学"、学晚了就当私聊。

**修法**（`adapter._load_group_ids` 扩展，连上就跑一次）：

1. 向协议端要 `get_group_list` → 灌满 `group_ids`（权威，不再靠"学"）；
2. 再加 `get_friend_list`（新 `_friend_ids()`）→ 主动名单里**不是好友/是群**的 id 一律清掉，
   日志留痕（`… 不是好友 → 已清掉（防假会话白烧回合）`）；
3. 拿不到好友名单就**不清**（宁可不清，不可误清）；协议端没起好时 3 段退避重试。

**实测**（重启后）：`群号名单 3 个` + `主动私聊名单里的 1***** 不是好友 → 已清掉`，
状态文件只剩 `<OWNER_QQ>` ✓。测试：`check_proactive` 用例加了 `123456` 必须被清的断言。

## 二、干活门（默认 profile）也加「退出冲缓冲」

**背景**：10-03 改的两轮节拍只在聊天门生效；10-04 主人要求干活门也两轮
（`/opt/data/hindsight/config.json` → `retain_every_n_turns: 2`）。但干活门用的是
**bundled 原版** provider，它的 `shutdown()` **不冲缓冲** → 被硬杀（容器重启/OOM）会丢最后那一轮。

**做法**：新插件 `plugins/hindsight_flush/`（`plugin.yaml` + `__init__.py`，约 80 行）：
只继承 bundled provider、只重写 `shutdown()` —— 缓冲非空时借 bundled 自己的
`on_session_switch()` 冲一次（和"切换会话"同一条路径，不自己造写库逻辑），随后原样 `super().shutdown()`。
其余行为 100% 委托。稳定性约定：冲缓冲整体 try/except（**任何异常都不许挡退出**）、
bundled 导入失败时退化成空壳、一行回退 `memory.provider: hindsight`。

**写的时候被测试抓到一次**：插件里第一次写了 `**self._forward_kwargs(...)` ——
bundled **没有**这个方法（那是聊天门闸门自己定义的帮助函数）→ `tmp/check_hindsight_flush.py`
直接报 `AttributeError` 且缓冲没冲掉。修掉后四项全过（含"冲缓冲自己炸了也不许挡退出"）。
**这跟 10-03 那个 `_group_of_session` 是同一类错误**：凭印象调"看起来该有"的方法。

**切换**：`config.yaml` 由 agent 不可改 → 用官方 `hermes config set memory.provider hindsight_flush` ✓
（`hermes config get` 复核 = `hindsight_flush`；子进程实测 `_get_active_memory_provider()` = `hindsight_flush`、
`load_memory_provider()` 返回 `HindsightFlushProvider` ✓）。
⚠️ **生效时机**：干活门网关下次启动（agent 不能重启自己所在的网关进程）。备份 `config.yaml.bak-before-flushprovider-*`。
