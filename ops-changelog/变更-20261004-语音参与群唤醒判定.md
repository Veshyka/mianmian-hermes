# 变更 2026-10-04：语音转写文本进群唤醒判定（她终于会被语音叫醒）

## 主人原话
「语音是不是不会参与概率触发他对话这件事儿…语音转文字，好像我一次都没有把他成功叫醒过，
哪怕这个语音理论上来说和它是强相关性」

## 根因（静态定位 + 线上实证）
唤醒判定读的文本是 `onebot_proto.extract_text(event)`（原始渲染），而 record 段在那层
**只有 `[语音]` 这个占位**（`MEDIA_PLACEHOLDER`）→ 对判定来说这条语音等于没内容。
线上日志逐字对上（12:19:25）：

```
group 未唤醒（群 <GROUP_ID>，模式=gated）：gated 未过闸 0.25<0.35｜+0.25 闲置压力
```

`0.25` 就是闲置压力，**内容贡献 = 0**。用他同一条语音的转写复现（脚本 `tmp/` 内）：

| 判定文本 | 分数 | 结果 |
|---|---|---|
| `[语音]`（占位，改动前） | 0.25 | 不唤醒 |
| `[语音: 测试一下语音是不是能够正常识别]`（改动后） | **0.90** | **过闸 → 叫醒** |

（0.35 疑问「是不是」+0.20 有信息量 +0.10 长消息 +0.25 闲置）

## 改了什么
1. `group_wake.py`：`decide()` 与 `gate_score()` 增加 `text=` 覆盖项（默认 `None` = 原口径
   `_text(event)`，行为逐字不变）。点名判定 `text_hits_alias` 同样吃覆盖项。
2. `adapter.py`：
   - 新增 `_group_score_text(event)`：有 record 段就返回**转写后**的判定文本，没有就返回 `None`。
   - `_group_wake_trigger(..., score_text=...)` → 传给 `decide`；
   - `_note_gate_incoming()` 也改用转写文本（门控里的「复读/刷屏」相似度按真内容算）。
3. **零额外成本**：转写本来就在窗口那条路（`_group_text_with_media`）做过了，结果缓存在
   `event["_voice_texts"]`，判定只是复用。没有语音段时 `_group_score_text` 返回 `None` → 老路径。

## 口径
- 语音现在**完整参与**唤醒判定：错觉词/求助词、信息量、长度、点名、对话态、复读 —— 全都按转写文本算。
- 静默窗/限流/记忆隔离硬前置/每次唤醒一个回合等护栏**一条没动**。
- 转写仍是「失败保 `[语音]` 占位」，此时判定只能看到占位 → 等价于改动前（不会误唤醒）。
- 群窗口里她看到的也是转写文本（这是上一条变更做的），所以唤醒与内容一致。

## 测试
- `tests/check_voice.py` +4：同一条语音「喂转写 → 过闸」「没转写 → 不过闸」的一对钉子、
  没有语音段时返回 `None`（原口径）、门控状态喂的是转写文本（按指纹比对，防「占位混进去」）。
- `tests/check_group_wake.py` +4：`gate_score`/`decide` 的 `text=` 覆盖项、语音里念她名字 =
  点名命中、`text=None` 必须回落原口径。
- 真复现：用主人那条群里语音的转写跑真 `gate_score`，0.25 → 0.90（见上表）。

## 回滚
`plugins/onebot/{group_wake.py,adapter.py}.bak-before-voicegate-<时间戳>`；
临时关掉语音转写（`voice_transcribe_enabled: false`）即回到占位口径。
