## 三、⚠️ 权限现实（这条决定"能不能真挂头衔"）

NapCat 只读查角色：机器人（<BOT_QQ>）在 **<GROUP_ID2> = admin**、<GROUP_ID3> = admin、
<GROUP_ID4> = member。QQ 侧规则：**头衔、上管理只有群主能操作**（管理员不行）；
禁言/踢人/撤回/精华/改群名/公告，管理员可以。

→ **在你们新群里她是管理员，所以 `[头衔:]` / `[管理员:]` 这两条大概率会失败**
（NapCat 会回业务错误，日志里能看到 `群管理 her_special_title → set_group_special_title 未成功`）。
要她能挂头衔，得把小号设成群主（或她本是群主的群）。
**未验证**：没有真在群里跑过一次（会改真实群资料），只在假群号上验到"参数通过、动作存在"。

## 四、勘误：`group_sessions_per_user` 的层级

* 上一轮把 `group_sessions_per_user: false` 只写进了 onebot 的 **extra** → **没生效**。
  证据：15:38–15:40 的群回合日志里会话键仍是 `...:group:<GROUP_ID>:<OWNER_QQ>`（带发言人尾号）。
* 真路径：`SessionStore._generate_session_key()` 用 **`self.config.group_sessions_per_user`**
  （GatewayConfig，即 config.yaml **顶层**；`gateway/platforms/base._source_session_key` 那条
  extra 路径只给 telegram/slack 之类兜底用）。
* 修法：在 `profiles/chat/config.yaml` **顶层**加 `group_sessions_per_user: false`；
  用官方读取器复核 `HERMES_HOME=/opt/data/profiles/chat hermes config get group_sessions_per_user` → **false**。
* extra 里那份**保留**（不冲突，保持两条路径一致）。
