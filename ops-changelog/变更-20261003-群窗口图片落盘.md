# 变更 2026-10-03：群窗口里的图/表情包现在带本地路径（动图也认）

**触发**：主人在群里发图 + 表情包，她只能看到「图片」「表情包」俩字；主人 DM 原话
「修一下，表情包那个是个动图」。

## 一、症状与根因（都是实测，不是猜）

群里三条消息的实际窗口记录（`onebot-groups/<GROUP_ID3>.jsonl`）：

```
{"t": "10-03 16:21:18", "name": "foresight每天都在焦虑", "text": "棉棉能提取出上面的文字信息吗[图片]"}
{"t": "10-03 16:22:36", "name": "<OWNER_NICK>",              "text": "[表情包]"}
{"t": "10-03 16:27:00", "name": "foresight每天都在焦虑", "text": "[表情包]"}
```

**关键矛盾**：`onebot-media/2026-10-03/` 里那几张图**其实都落盘成功了**
（`e09e07f5d4cfa0f3.jpg` 201KB＝主人发的 864×1920 照片，`8977b52f40038825.gif` 572KB、
`85e10f0e67b18cf5.gif` 772KB＝两张表情包，日志 `图片落盘` + `表情包入库` 都在），
**但路径没进窗口文本**。

原因在 `adapter._ingest` 的顺序：媒体落盘（`_text_with_media`）跑在**唤醒判定之后**、
且只作用在**触发那一轮的那条消息**上；而群回合的正文来自**滚动窗口**
（`group_window` → `extract_window_text`），窗口里存的一直是 `[图片]` / `[表情包]` 占位。
于是：图落了盘 → 她这轮看的却是窗口里的占位 → 只能看到俩字。表情包（`sub_type=1`，
QQ 里就是动图）走的是同一条链，一样只剩字。

## 二、改法：**先落盘，再入窗**

`adapter._ingest` 群分支：

```python
win_text = await self._group_text_with_media(event)   # 新增：窗口口径 + 本地路径
self._collect_group(event, gid=gid, uid=uid, text=win_text)   # 入窗的文本带路径
```

* 新增 `_group_text_with_media()`：`with_media_paths(extract_window_text(event), paths)`；
  受新开关 **`media_group_download`（默认 true）** 控制，关掉即退回旧行为。
* `_collect_group(..., text=None)`：允许外部传入已带路径的文本。
* 落盘结果仍缓存在 `event["_hermes_media_paths"]` → 稍后 `_text_with_media()` **不会重复下载**。
* 上限未变：`media_max_per_msg=4`、`media_max_bytes=8M`；`media_download_enabled=false` 依旧是总闸。
* 顺带效果：不唤醒她的那些消息里的表情包，现在也会进她的表情库（`_register_sticker` 同一处）。

**动图（GIF）能不能看**：实测可以。`vision_analyze` 读
`onebot-media/2026-10-03/8977b52f40038825.gif` 能描述出画面内容（灰发鹿角 Q 版角色），
说明视觉链路自己会取一帧，不需要转码 → **不做 GIF→PNG 转换**，直接把 `.gif` 路径给她。

**代价（明说）**：群里的图不再"只在她被叫醒时才下载"。带图消息的接收循环会多等一次
`get_image`（百毫秒级；纯文本消息不受影响）。要省带宽/磁盘就把 `media_group_download` 设 false。
