# 变更 2026-10-03：入群审批真自审（原来通知发到了主人私聊）

**触发**：主人看到聊天门推来两条「加群申请待处理：<APPLICANT_QQ>…按配置需要你手动决定，我没有替他动手」，
回「我配置不是让你自己决定吗」；随后补充：「我是想让她能直接自己看到申请并看是不是通过，我更倾向于宽松审核，
反正要入群都会说几句话，有问题踢。你看看能不能复用你回执到她那个通道（可唤醒 AI 那种，申请一小时不要给她发太多，
不要反馈到群里）」。

## 根因（一句话）

`request_type` 判断错了，两条路一起错：**适配器只认 `"add"`，NapCat 发的是 `"group"`** ——
所以「她自己审」的回合从来没起来过；而 `group_admin` 的 `policy: manual` 那条路照常跑，
产出 `_owner_notice(...)` → `send_private_msg`（日志 16:25:29 / 16:26:34 两笔）→ 主人私聊里那两条。

**测试为什么没抓到**：`check_admin_outbound.py` 的夹具 `_req()` 里写的是 `"request_type": "add"`
—— **照着 bug 造的数据**，两边一起错，61 例全绿。
证据：`group_admin._handle_request` 首行 `if _proto.request_type(event) != "group": return self._skip(...)`，
线上确实产出了 `request_manual` → 真值只能是 `"group"`。

## 改了什么

| 位置 | 改动 |
| --- | --- |
| `adapter._route_group_admin` | 认 `request_type in ("group", "add")`（兼容旧实现），注释写明来源 |
| `group_admin.POLICIES` | 新增 `agent`：**不动手、也不通知主人** —— 交给她自己审 |
| `config.yaml` | `group_admin.request.policy: manual → agent`；`notify_owner: false`；新增 `join_review_max_per_hour: 1` |
| `adapter._review_join_request` | ① 每条申请**先**在群窗口留系统记录（审不审都留，事后能踢人）；② 每小时唤醒上限从配置读（默认 1）；③ **超限直接静默放行**（宽松、不烧钱）；④ 派发前置 `_silent_group_turn` |
| `adapter._approve_join_silently`（新） | 直接出 `set_group_add_request` 帧，不发消息、不唤醒 AI |
| `adapter.send()` | 审申请那一轮：群管理标记照旧生效，**正文丢掉**（「不要反馈到群里」），300s 过期 |
| `group_wake.JOIN_REVIEW_NOTE` | 措辞改「默认宽松放行…拿不准也放进来…这一轮别在群里说话」 |
