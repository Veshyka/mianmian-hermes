# 待办：A2A 派活「回不来」

> 状态：**未做，等主人发话**（2026-09-23 主人说"你先记下来，等会再说"）
> 记录人：棉棉（干活门）。解冻时从这一份直接续，不用重新查。

---

## 症状（主人原话）

> 「让他把活派出去之后，他会一直盯到 5 分钟窗口结束才回来。」
> 「他说会加强干活门回执，就是在有回执之后就立刻停手。但是事实上，好像他还是做不到把活一派出去就回来。」

即：聊天门派活给干活门后**不能立刻返回**，会耗满 300 秒。

---

## 根因（已逐层验过，不是猜的）

1. 聊天门调 `a2a_call` → `_send_task()` → **一个阻塞的 HTTP POST**
   （`/opt/hermes/plugins/platforms/a2a/tools.py:96-130`）
2. 干活门收到 → `_prepare_task()` 里 `fut = self._add_pending(...)`
   → **HTTP 响应被挂住，等到整个 agent 回合跑完才返回**
   （`/opt/hermes/plugins/platforms/a2a/adapter.py:560-573`）
3. 干活门的回合是真在干活的
4. 聊天门 `a2a_agents.work.timeout: 300` → **等满 5 分钟放弃**

### 实测证据（干活门 log，2026-09-23）

```
response ready: platform=a2a time=1508.9s api_calls=53   ← 25 分钟
response ready: platform=a2a time=161.3s  api_calls=19
response ready: platform=a2a time=152.5s  api_calls=8
```

---

## 为什么「加强干活门回执」这个思路不成立

**这个通道是请求/响应，不是流。** 干活门在回合中间说多少遍"已接单"，聊天门都收不到 ——
它卡在等 HTTP 响应，而响应只在回合结束时才产生。

顺手验过的另一条路：A2A 支持推送回调
（`configuration.taskPushNotificationConfig`，HMAC 签名 `X-A2A-Signature`），
但读 `_prepare_task()` 发现 **注册回调之后它照样 `_add_pending` 挂住响应** ——
推送只能"额外抄送一份"，**不能让调用方立刻脱身**。此路不通。

**另外这条账要算在干活门头上**：SOUL 里"长任务两段式"写着"秒回一行 ✅ 已接单"，
但干活门一直是在回合里把活干完才回。Hermes 一个回合只产出**一条**最终消息，
所以"边说边干"在单回合内本来就做不到 —— 规则写得对，落地路径没给。

---

## 解法（三步，缺一不可）

### A. 干活门必须秒级结束回合 ← 根本
收到 A2A 任务 → 把长活丢给**后台进程 / 定时任务** → 回"✅ 已接单 + 结果会写到哪" → **回合立刻结束**。
真正的工作在回合外跑。

### B. 跑完推回去 ← ✅ **基建已经现成，不用重造**
后台跑完 → 干活门调一行命令把回执投给聊天门 → 聊天门自己判断要不要告诉主人。

```bash
python3 /opt/data/scripts/receipt_to_chat_door.py \
    --summary "…" --paths "…" --status "完成"
```

（= `a2a_call` 的脚本化包装，走官方 A2A 的 JSON-RPC `SendMessage`。详见
`ops-changelog/README.md` **§2.5**，那里还有落点会话、反循环闸、验证三连。）

**⚠️ 但它有个致命的语义缺口，动手时必须一起解决：**
回执落在 `agent:main:a2a:dm:worker-receipts` 这条**和主人私聊完全不相通的会话**里。
`README §2.5` 原话：**"A2A 里她说的话主人看不到"**。
主人要真知道，只能靠聊天门自己走三档里那档
`cronjob_manage(deliver="onebot:<OWNER_QQ>")` 转发 —— 也就是说 **B 通了 ≠ 主人收到**。
这不是新发现，是已知设计，但正好是"派活后回不来"这件事的用户体感来源之一。

### C. 超时收紧 300 → 90
理由：A 做了之后回执本该几秒内到；**90 秒还没回 = 干活门没守规矩**，早失败早暴露。

⚠️ **A 必须先做。** 只改 C 会让每条任务都在 90 秒被判失败，比现在更糟。

**不建议**：动 `/opt/hermes/` 里的 A2A 插件去加真异步（SSE / 解阻塞）——
那是公共代码，升级就丢，收益不如 A+B。
