# 变更 2026-10-03：mihomo 代理「订阅能拉、节点全连不上」的根因（UA 分流端点集）+ 告警降噪

**触发**：主人「我怎么老看到这个」（反复收到看门狗告警）。

## 一、根因（子代理深挖 + 本人复核）

**机场按 User-Agent 返回的不是「格式」差异，而是两套完全不同的端点集：**

| UA | 节点数 | 端点裸 TCP 实测（宿主侧） |
|---|---|---|
| `sing-box/1.9` | 102 | **99/102 可连、TLS 68/102 握手成功** |
| `mihomo/1.19.0` | 102 | **0/102**（26 refused + 76 timeout，TLS 0） |

- mihomo 日志的真实报错是 `connect error: dial tcp <ip>:20177: i/o timeout`（不是 DNS 失败、不是 refused、不是 SSL）→ 端点已退役。
- 宿主直连 Cloudflare / Fastly / 国内全通 → **本机网络没被封**；换 UA 立刻拿到活端点 → **排除账号超限/到期**。
- 路由器 OpenClash 存的是**同一条订阅**（URL md5 前 6 位一致），它能通只是因为**它用的 UA 不同** —— 所以「路由器能通」在本案里证明的是 UA 差异，不是订阅差异。
- **看门狗逐轮自愈的旧逻辑用的是 `mihomo/1.19.0`** → 每次自愈都把整套死端点重装回去 → 两级自修全失败、代理反复坏（10-01 起三天），这就是主人反复看到告警的根。

## 二、已做的动作

1. **看门狗改为按序试 UA**（`sing-box/1.9` 优先，`mihomo/1.19.0` 兜底）+ **端点裸 TCP 校验**，选能连上的那套再写配置。
2. 重拉订阅 → 重写配置 → 重启 mihomo。
3. **告警降噪**（主人嫌响太勤）：
   - 连续不通 **≥3 轮（约 1.5h）** 才发（新状态 `cache/mihomo/down_streak`，恢复清零）
   - **每日硬上限 1 条**（新状态 `cache/mihomo/last_alert_day`，恢复时**不删**、次日自然重置）
   - 保留 6h 冷却作为二级闸
   - 旧行为「恢复时删 `last_alert`」已去掉——正是它让「反复坏」变成「反复响」
4. 单测 `/opt/data/tmp/test_mihomo_alert.sh`：把真脚本的 `emit_alert` 抠出来测 9 种情形（不碰网络），**9/9 通过**。
