# 变更 2026-10-04：私聊不再自动引用（群聊保留）

## 主人原话
「为啥每一次他发消息都会引用我第一条信息？其实，如果没必要引用，那就别引用啊。
感觉每一条都引用怪怪的。」

## 根因（不是她故意引用）
引用段来自 **Hermes 的通用机制**：`gateway/stream_consumer.py` 把「这条响应对应哪条入站
消息」当 `reply_to` 传下来（`initial_reply_to_id = event_message_id`），适配器照做就带上
`{"type":"reply","data":{"id":…}}` 段。私聊里「触发那条」= 他**这一轮的第一条消息**
（防抖会把连着发的几条并成一轮）→ 于是每条回复都挂着「引用他第一条」的观感。

## 改法
- 新增纯函数 `_auto_quote(is_group, reply_to)`，在 `send()` 里对传下来的 `reply_to` 过闸：
  - **私聊：默认丢掉**（`auto_quote_dm: false`）
  - **群聊：默认保留**（`auto_quote_group: true`，群里有上下文价值）
- 丢的只是引用段，**正文照发**（不许因为不引用把消息吞了）。
- **显式引用不受影响**：她真想引用哪条，自己在正文写 `[CQ:reply,id=…]`，`cq_to_segments`
  照旧转成 reply 段。= 「有必要才引用」由她自己决定。
- 连带效果：私聊「贴表情」的目标从「她正在回复的那条」退到「该会话最近一条入站消息」——
  也就是他认为的那条，行为不变合理。

## 开关
`auto_quote_dm`（默认 false）、`auto_quote_group`（默认 true）。

## 测试
`tests/check_quote.py` 8 例（真反向 WS + 假协议端，看她线上到底发出什么）：
私聊发出 `send_private_msg` 且 message 里**没有** reply 段、正文一字不少；私聊不带 reply_to
时行为不变；私聊里显式 `[CQ:reply,id=999]` 仍然引用且 CQ 码不漏成字面文本；群聊仍然引用；
两个开关都能翻；纯函数默认值；默认值就是文档里写的那两个。

## 回滚
`plugins/onebot/adapter.py.bak-before-autquote-<时间戳>`；或配置 `auto_quote_dm: true` 回到旧行为。
