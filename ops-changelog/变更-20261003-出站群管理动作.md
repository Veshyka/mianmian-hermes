# 变更 2026-10-03：她能自己管群了（出站群管理动作）

**触发**：群里主人问「理论上你应该可以用禁言这种群管理工具啊」，她答「出站只接了发消息，禁言那条线没接过来」→ 主人「新任务」。

## 一、结论先说：她之前那句是**对的一半**

- 群管理模块（`group_admin.py`，809 行）**一直都在**，而且线上是**开着的**（`group_admin_enabled: true`、重启后 `group_admin_active: true`）——它管的是**入站**：欢迎语、防撤回、违禁词、加群审批、`/` 前缀的 owner 命令。
- 缺的是**出站那条线**：她（LLM）在群里的回复只能变成消息，没有任何「动作」通道 → 所以她「知道有工具但手伸不过去」。

## 二、改了什么（三处）

| 文件 | 改动 |
|---|---|
| `onebot_proto.py` | 新增 `ADMIN_MARKERS` / `ADMIN_MARKER_RE` / `extract_admin_markers()`：把正文里的 `[禁言:QQ号,秒数]`、`[解禁:QQ号]`、`[踢出:QQ号]` 剥出来 → `(干净正文, 动作列表, 认不出的写法)`。仿 `[贴表情:x]` 的既有约定。 |
| `adapter.py` | `send()` 里在 `is_group` 判定后**剥标记并发动作帧**；新增 `_admin_intents()` 承载全部硬护栏；新增 `_as_int_safe()` |
| `group_wake.py` | 回合正文里教她标记写法 + 动手尺度（只有「明显刷屏/广告/辱骂」或「主人让你管」才动手，拿不准只说话） |

**为什么不用消息段**：动作不是消息。混进 `message` 数组会被协议端当未知段拒掉
（`retcode=1200 消息体无法解析` → **整条消息发不出**，同一天 `face id=500`、未知 CQ 码那两起）。
所以走**独立动作帧**，与贴表情同一条规矩：标记先剥、动作后发。

## 三、硬护栏（代码级，提示词拦不住的那层）

| 护栏 | 行为 |
|---|---|
| 目标 = 主人 | **拒**（`trust_tier_owner_ids` 解析出 `<OWNER_QQ>`），日志 `目标(29***)是主人 → 拒绝执行` |
| 目标 = 她自己 | 拒（禁言自己等于把自己关掉） |
| 时长 | 钳在 **60s ~ 2592000s（30 天）**；省写默认 300s |
| 场合 | 只在**群聊**执行；私聊出现标记 → 剥掉不执行 |
| 次数 | 一条消息最多认 **3** 个动作，多的丢弃并记日志 |
| 号码 | 非数字 → 剥掉 + 记 unknown（绝不当字面文本漏给主人） |
| 记账 | 每个动作进日志（目标只打 `qq[:2]+***`）+ `group_admin_actions` 计数 |

## 六、第二批（同日追加）：审批 / 撤回 / 全体禁言

主人在群里问「如果有人进群能不能审批」，她答「审批没接上来，进来之前那一步我还管不着」→ 补上。

| 标记 | 动作帧 | 说明 |
|---|---|---|
| `[同意入群:QQ号]` | `set_group_add_request {flag, sub_type:add, approve:true}` | **flag 她自己看不到**，靠适配器存的待审批队列按 QQ 换 |
| `[拒绝入群:QQ号,理由]` | 同上 `approve:false` + `reason`（理由限 60 字） | 一条申请只批一次，用过即从队列移除 |
| `[撤回:QQ号]` | `delete_msg {message_id}` | 她的上下文没有 message_id → 用 `MessageCache.last_mid_by_user()` 翻出「这个人最近一条」 |
| `[全体禁言:开\|关]` | `set_group_whole_ban {enable}` | 无目标 |

**新增的护栏**：

- 待审批队列：`OrderedDict`，容量 20，**TTL 24 小时**；过期申请自动作废（防她拿旧 QQ 号乱批）
- **没有对应待审批申请 → 什么也不做**（不许凭一个号码批人进来）
- 撤回找不到缓存里的消息 → 不做（不猜 id）
- 目标=主人 / 目标=她自己 依旧全类型拦截（含 recall / reject_join）
- 队列只装 `request:add` 事件（`flag` 只在事件里出现一次，她看不到 flag 是设计前提）

**她怎么知道有人申请？** 现状：`request.policy: manual` + `notify_owner: true` → **通知主人**（含申请人 QQ），
主人跟她说一句「同意那个 12345」即可。**她自己在群里看不到申请** → 要让她自主审批，
得再给群窗口注入一行「有人申请入群」episode（未做，需主人点头）。

## 九、第三批（同日追加）：她自己审入群申请（主人：「加上吧，这个让她自己审不要让别人提醒」）

之前只做到「申请 → 通知主人 → 主人转告她」。现在改成**申请直接进她的一轮**：

1. `request:add` 事件进 `_route_group_admin` → 存 flag 进 `_pending_joins`（原有）
2. **新增** `adapter._review_join_request()`：
   - 往该群滚动窗口写一条**系统记录**：`[系统]: 有人申请加入本群。申请人 QQ：xxx；附言：yyy`
     （她下一轮一定看得到，且以后翻窗口也看得到）
   - 按 `trigger="join_request"` 调 `_dispatch()` → 正常起她的回合
3. `group_wake.build_turn_text()` 对 `join_request` 走**专用正文**：不是「回应末尾那句」，
   而是任务说明 —— 像正常人就批、像广告小号就拒、拿不准就不动（申请留着）、不用问主人
4. 她的回复经 `send()` → `[同意入群:QQ号]` 换成真 `set_group_add_request` 帧

**节流（防申请洪水烧钱，都在代码里）**：

| 护栏 | 值 | 理由 |
|---|---|---|
| 每群冷却 | 60 秒 | 连来两个申请不连起两轮 |
| 每群上限 | 10 次/小时 | 洪水式申请（几十个）不会变成几十个付费回合 |
| 群唤醒=collect-only | 不审只记（flag 照旧进队列） | 不唤醒档位的红线不被新路径绕过 |
| `group_enabled=false` | 直接不碰 | |

**她看不到 flag 这件事没变**：flag 只在事件里出现一次，她拿到的永远是 QQ 号，
适配器按号换 flag —— 所以「胡乱批人」在代码层面不成立（没有队列项就发不出帧）。

**已知取舍**：`_pending_joins` 是内存态，**重启丢**（丢了她就没法批，得让申请人重来）。
申请本身不会被吞（`group_admin` 仍按 `request.policy: manual` 通知主人一次，留痕备查）。
