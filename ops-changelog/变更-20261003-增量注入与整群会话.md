# 变更 2026-10-03：群上下文改成增量注入（取消重复）+ 整群共用一条会话

**触发**：主人追问"30 条到底怎么发的"，认清是**滑动窗口**（每轮都发最近 30 条，跨轮重叠）后拍板：
> 「取消重复的部分，因为上下文它是完全能看得到的……而且一次性发一堆会更快的触发那个压缩。
> 而且依赖会话历史没什么问题，包括被压缩或者被重启断片都挺好，其实都能接受。」
> 「整个群共用一个会话更好，更连贯——我就说怎么另一个人发言出现了新对话提示。」

## 一、整群共用一条会话

* 配置：`profiles/chat/config.yaml` → onebot extra 加 `group_sessions_per_user: false`
* 备份：`config.yaml.bak-before-group-session-20261003-152442`
* 验证（用 Hermes 自己的 `gateway.session.build_session_key` 跑真函数）：

```
per_user=True （旧）主人 → ...:onebot:group:<GROUP_ID>:<OWNER_QQ>
per_user=True （旧）别人 → ...:onebot:group:<GROUP_ID>:<OWNER_QQ2>   ← 换人说话=另起对话
per_user=False（新）两者 → ...:onebot:group:<GROUP_ID>
```

* 副作用（已向主人说明）：群里所有人共用一条上下文；群聊内容**仍不进主记忆库**
  （每轮带 `source=qq-group`，`hindsight_guard` 拦着）。
* 旧那条 74 条会话的 prompt 已涨到 **87k tokens**，不再使用 —— 换会话后每轮从 ~2 万起步。

## 二、增量注入（delta）：只发"上次之后的新消息"

* `group_window.delta_since(gid, cursor, limit)` + `render_records(..., delta=True)`
  （游标用记录本身当标识 `(ts, uid, text)`，**不改 schema**）
* `adapter._group_turn_text()` 按 `group_context_inject_mode` 分发；游标存 `_group_inject_cursor`（每群一个，内存态）
* `group_wake.build_turn_text(..., ctx_mode="delta")` 换掉引导语："上次你被叫醒之后新增的消息……
  更早的内容在你自己的对话记忆里，不重复发"

**三道安全网（宁可多给，不许断片）**：

| 情形 | 行为 |
|---|---|
| 首次唤醒 / 刚重启（无游标） | 退化成"最近 N 条"打底 |
| 游标已被窗口淘汰（>200 条） | 退化成"最近 N 条" |
| 久未唤醒，新增几百条 | 只取最新 `group_context_inject_msgs`（30）条 |
| 渲染异常 | 记 `group_window.errors`，唤醒照常（不炸回合） |

**回滚**：配置改 `group_context_inject_mode: window` → 立刻回到"每轮发最近 30 条"。
