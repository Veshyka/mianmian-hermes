# 变更 2026-10-04：把 Hermes 的「静默提示」关掉（主人：一步到位）

**触发**：主人贴出她发来的 `⚠️ The model returned only a silence marker for a message that needed a reply.`
并说「看来还是不行啊，干脆把她提示都关了，一步到位解决」。

## 它到底是什么（先澄清，免得误判成新功能的 bug）

不是表情包/打标那条线的事。这是 Hermes 的**通用机制**：

* 她在某个回合只回了**静默标记**（表示"没话说"）；
* Hermes 认为这一轮是**人回合**（主人找她）→ 不允许静默 → 把正文替换成
  `gateway/run_turn.py` 里的 `_UNEXPECTED_SILENCE_REPLY`（那段 ⚠️ 文案），并记
  `silence marker rejected on a user turn`；
* 这段文案原本会**原样发出去** → 主人看到的就是这条 ⚠️。

日志实测（`profiles/chat/logs/gateway.log`）：共 **3 次**，全在主人私聊
—— `2026-10-03 22:05:01`、`2026-10-04 12:56:20`、`2026-10-04 21:28:29`。

## 改了什么（`plugins/onebot/adapter.py`）

`send()` 里加一道闸（放在 `_proactive_activity` 之后 —— 这段不是"她开口了"，不该把她主动起头的斜坡归零）：

```python
if _is_silence_warning(content):        # 特征串 "The model returned only a silence marker"
    self._silence_warn_suppressed += 1  # 只记账
    logger.info("[onebot] 吞掉 Hermes 的静默提示（她这轮没话说）：%s（累计 %d 次）", ...)
    return SendResult(success=True, message_id=None)   # 不发
```

* **私聊、群里都不发**（主人说"都关了"）——否则她在群里"装死被拆穿"的话会被外人看到；
* 用**特征串**判，不依赖 emoji 前缀（emoji 在日志/终端里容易被吃掉）；
* 记账 + 日志，**不是黑洞**（`_silence_warn_suppressed` 计数 + 一行 INFO）。

## 明确**没有**动的东西：私聊里的静默标记本身

`test_silence_marker_does_not_work_in_private` 钉着一条老决定——**私聊里她不能拿静默标记挡**：
那个场景下标记会当普通文本发出去（主人一眼看得出她在装死），群聊才吞。
这次改动**不动这条**（第一版顺手把群聊的限制放到了私聊，被那条测试抓住 → 已还原）。
