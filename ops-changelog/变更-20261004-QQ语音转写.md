# 变更 2026-10-04：QQ 真实语音 → 文字（她终于听得见）

## 起因
主人发语音，她只收到 `[语音]` 空壳：「我这边只收到个 [语音] 的空壳 / 声儿一点没进来」。
根因：`onebot_proto.MEDIA_PLACEHOLDER["record"] = "[语音]"` —— record 段只被渲染成占位，
**从来没有人去取音频、也没人转写**。

## 摸清的链路（每条都实测过）
| 步骤 | 事实 |
|---|---|
| record 段字段 | `file`（如 `dfe7ad0b….amr`）、`path`（`/app/.config/QQ/nt_qq_*/nt_data/Ptt/2026-10/Ori/….amr`）、`url`（QQ CDN，带 rkey）、`file_size` |
| 那份 `.amr` 是什么 | **不是 amr**：本机 ffmpeg 7.1.5 直接 `Invalid data found`（QQ 把 silk 换皮成 .amr） |
| 谁转得动 | 协议端走 **silk**：`get_record(file=…, out_format="mp3")` → 回 `base64`（整段 mp3）+ 落好的本地路径 |
| 共享卷 | NapCat 的 `/app/.config/QQ` = 宿主 `/vol1/1000/<USER>` = 她的 `/opt/data/stack/napcat/ntqq` → **同一份文件她直接读得到** |
| 转写 | 她的 whisper：`POST http://172.17.0.1:8090/v1/audio/transcriptions`（speaches，`Systran/faster-whisper-small`，`language=zh`）|
| 真样本实测 | 主人那条 5″ 语音 → **"我现在还是在外面呢等会我要去帮我妈拿东西"**（整条链路 1 次成功）|

## 改了什么
1. `plugins/onebot/onebot_proto.py`：加 `record_segments(event)` / `with_voice_texts(text, texts)`
   —— 只负责「认段」和「把 `[语音]` 按顺序回填成 `[语音: 文本]`」。
2. `plugins/onebot/adapter.py`：
   - `_voice_texts()`（失败单条不影响别的、结果缓存在 event 上，群窗口先跑过就不再重复取）
   - `_voice_blob()`：WS 动作 `get_record(out_format=mp3)` → 优先 `base64`，兜底读本地路径（含容器前缀映射）
   - `_transcribe_voice()`：落盘（强制 `.mp3`，别落成 `.bin`）→ 转写
   - `_stt()`：OpenAI 兼容 `/v1/audio/transcriptions`
   - 接线：`_text_with_media()`（私聊）与 `_group_text_with_media()`（群窗口）都过一遍
   - `_save_blob()` 支持指定扩展名
3. `profiles/chat/config.yaml`：`voice_transcribe_enabled / voice_out_format / stt_url / stt_model / stt_timeout`

## 口径（钉在测试里）
- **失败一律保留 `[语音]` 占位**：取音频失败、协议端 retcode≠0、STT 5xx、转出空串、超 `media_max_bytes`
  —— 全都退回占位，绝不抛异常、绝不吞掉整条消息。
- 一条消息多条语音按顺序回填，互不影响。
- `voice_transcribe_enabled: false` → 完全退回空壳行为（回归开关）。
- 先落盘再入窗（跟图片同一条规矩）：音频落 `onebot-media/<日期>/<sha256前16>.mp3`，天然去重。

## 测试
- 新增 `tests/check_voice.py`（12 例）：私聊/群窗口两条路、多条按序、路径兜底、5 种失败路、
  关开关、单次取用、纯函数边界。STT 用**进程内假服务**（不打外网）。
- 端到端冒烟 `tmp/smoke_voice.py`：拿主人**真实那条语音**的 NapCat 真响应 + 真 whisper，
  跑她真实代码路径 → `[语音: 我现在还是在外面呢等会我要去帮我妈拿东西]`。

## 回滚
`git` 不在这个目录，靠备份：`plugins/onebot/{adapter.py,onebot_proto.py}.bak-before-voice-<时间戳>`；
配置侧把 `voice_transcribe_enabled` 改 false 即可立刻退回空壳行为。

## 已知边界
- 只转**中文**（`language=zh` 写死）；以后要夹英文得改成不传 language 或按需。
- 语音上限沿用 `media_max_bytes`（8 MB）；超了不转写。
- 群里 99% 的消息不唤醒她：只有**进窗口**的消息才转写（和图片同一条成本口径）。

## 事故教训（同一天，记在这）
12:19:34 群里那条语音**唤醒了**她（`触发=at`，`GROUP message -> agent turn`），但我 6 秒后重启了她的网关
→ 群回合被掐断，她一个字都没回（主人以为「群聊语音没按预期工作」，其实群窗口里
`[语音: 测试一下语音是不是能够正常识别]` 已经转出来了）。顺带解释了同一次重启后的那条
`retcode=1200 无法获取用户信息` 发送失败：被掐断的回合的 outbound 在启动时冲出去，那时 NapCat 刚重连完还没就绪。

**规矩：重启她的网关前，先看日志确认没有正在跑的回合**（`grep 'GROUP message -> agent turn\|inbound message'` 最近几条 + 看有没过几秒的停顿）；
赶时间也要等回合落地——掐断一次群回复，主人那边看到的是「功能没生效」。
