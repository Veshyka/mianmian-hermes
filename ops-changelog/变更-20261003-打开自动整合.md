# 变更 2026-10-03：打开 Hindsight 自动整合（bank 级 override）

**触发**：21:00 的「记忆质量回看」cron 报出「变更 1 名义开、实际关」；主人拍板「现在就打开，反正这个多排一会不影响」。

## 一、根因（回看报告 + 现场复核）

开关是两层，**bank 级 config 覆盖 env**：

- compose env：`HINDSIGHT_API_ENABLE_AUTO_CONSOLIDATION=true`（10-02 的「变更 1」）
- bank config：`enable_auto_consolidation=false`（更早那次「整合成本太高、先关」的落盘值）
- 结果 `GET /config` 的 resolved 值是 `false` → `banks_needing_consolidation()` 的 SQL 门排除本 bank，
  日志里 `Consolidation reconcile: scheduled` 出现 **0 次**，retain 侧的
  `enable_observations and enable_auto_consolidation` 门也一起被挡。
- 后果：积压 `pending_consolidation` 只涨不降（当时 **422**，约 +33/h），无人再排。

## 四、代价与预期行为

- **抢唯一槽**：`WORKER_MAX_SLOTS=1`、`WORKER_CONSOLIDATION_RESERVED_SLOTS=0` → 整合与 retain 共用一台
  27B，谁先占谁跑；主人已明确「多排一会不影响」。
- **会自排链**：一轮撞 `consolidation_max_memories_per_round=100` 会无条件续下一轮，直到剩余 <100
  自行终止（10-02 那晚就是这么停在 00:58）。**要停**：趁下一轮还是 `pending` 时 `DELETE /operations/{id}`，
  或把 bank 值改回 false（不影响已在跑的那轮）。
- ctx 溢出风险已随 llama-extract `-c 32768` 消失（近 20 次 LLM 调用 20/20 成功）。
