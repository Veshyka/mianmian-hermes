# 变更 2026-10-03（下午）：群聊唤醒加「对话态」——不 @ 也能接话

**触发**：主人在群里实测发现「她只认 @」——不 @ 的消息她要么不醒，要么只在下次被 @ 时才看到。主人要求：**能看到不 @ 的消息，并且可以主动插话**。

## 一、现场取证（先复现，再动手）

- `profiles/chat/onebot-state.json`：`group_wake_mode=gated`、`group_gate_threshold=0.35`、`group_rx_count=8`、`group_llm_calls=3`、`group_mention_count=3`、**`group_full_count=0`**。
  → 本次会话里 3 次唤醒 **全部来自 @**，免费闸一次都没放行过。
- `profiles/chat/logs/agent.log`：非 @ 消息只有 `group collected`，没有 `[onebot] 群唤醒（触发=gate）`。
- 离线重放真实窗口（`onebot-groups/<GROUP_ID>.jsonl`，32 条）用当前代码算分：
  - 「群聊上下文能看见几条」0.20、「应该现在会认人了」0.21 → **都低于 0.35，被拦**
  - 带疑问词的「最近不是改动挺多吗」0.55 → 本该过闸
  - 根因一：普通中文消息只能拿 `+0.20 有信息量`，**卡在阈值下方**，只有含「吗/怎么/为什么」等信号词才过
  - 根因二：`reason == "none"` 的判定日志是 **debug 级** → 线上根本看不见「她为什么没醒」，排查无从下手

## 二、改动（增量、可回滚）

| 文件 | 改动 |
|---|---|
| `profiles/chat/plugins/onebot/group_wake.py` | `GateState` 增 `conv_until` + `note_conversation()` / `in_conversation()`；常量 `CONV_WINDOW_S=180`、`CONV_BONUS=0.45`；`gate_score()` 增 `conv_bonus` kwarg（对话态 +0.45） |
| `profiles/chat/plugins/onebot/adapter.py` | ① 任意一次唤醒后进/续对话态；② 她发言成功后进/续对话态；③ 非唤醒判定 **debug → INFO** 留痕 |
| `tests/check_group_wake.py` | 新增 `TestConversationState`（4 例：潜水态拦/对话态放、窗口过期、纯表情不受益、窗口只延长不缩短） |

语义：**潜水态靠免费闸筛（省钱）；对话态（她说过话后 180 秒内）直接放行（连贯）**。窗口内她仍可用 `[SILENT]` 闭嘴；纯表情/≤2 字即使在对话态也不唤醒；@ 通道不受影响，且被限流仍必须留痕。
