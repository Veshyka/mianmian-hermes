# 聊天 agent（陪伴向）方向把握清单

> 用途：**派活/评审的依据**。任何关于"聊天门怎么做、要不要换、算不算成功"的任务，先读这一页。
> 立场：不是"把 AstrBot 的功能搬过去"，而是**在 Hermes 里做一份陪伴向特调**。AstrBot 是参照样板，不是要复刻的成品。

## 一、归因（**已结案 2026-09-23**）

**结论：主人 100% 确认「说话像人」来自提示词形状**——小人格 + 示例 + 节奏那一套。不是模型、不是通道符号、不是工具面宽度。
主人已拍板**取消盲评对比**，`单变量对照` 那批实验不用再补。

- 历史假设（留痕用）：「AstrBot 说话像人」的候选因素 ① prompt 形状（小人格 vs 工作规则书）② 模型（deepseek-flash）③ 通道节奏（分段 `⁂` + 防抖 10s）④ 工具面宽度。
- 曾设想的方法：**单变量对照**（同模型换 prompt 形状；固定 prompt 换模型）+ 人工盲评（主人挑）。
- **已作废**：不再做盲评对比；原先那条「未完成此项之前，不要下『搬过去就行』的结论」的闸门随之解除。
- 仍成立的推论：**搬家时必须原样带走的是提示词形状**（陪伴向写法：少规则、多示例、写节奏、工具面窄）；模型、通道、工具面都是可替换的实现细节。

## 二、陪伴型 vs 干活型：提示词是两种形状

| | 陪伴向特调 | 干活型 |
|---|---|---|
| 规则量 | 少（写成性格与反应方式） | 多（流程、边界、禁令） |
| 示例 | **要有**（user/AI 几组样例） | 可无 |
| 节奏 | 明确（何时一句、何时多句、何时主动开口） | 不关心 |
| 输出 | 不给结论、不说教、不列清单 | 结论先行、结构化 |
| 工具面 | **窄**（每多一个工具多一分汇报腔） | 全开 |
| 记忆 | 常驻固定事实 + 按话题召回 | 常驻 + 召回 + 工作日志 |

**红线**：不得把工作型 SOUL 直接搬过去当聊天人格。工具 schema 会计入系统提示词（实测：Hermes chat profile 人格+工具约 9,273 token），既影响成本也影响语气。

## 三、工具面闭集（收窄的下限）

定法：**按"能否一步做完"划分**。

- 给：**查询**（网页搜索 / 单页正文 / 视频信息与字幕）· **记忆**（召回、常驻记忆读写）· **派活 1 个**（`a2a_call`）· **说话自己要用的**（主动发消息、定时）· **文件四件套**（读 / 写 / 改 / 搜 —— 看主人发来的东西、按他说的写点东西）。
- 砍：shell / 解释器 / 子代理编排 / 运维类。
- **砍掉 ≠ 不能做**：凡是多步、要中途改方向、要登录态的，一律转手派出——所以"窄"不等于"传话筒"。**派活的理由要用大白话说**：干活门那边主人能随时喊停、一句话改方向（Hermes 有 `/stop`），她这边不行 —— 一开始就只能走到底。
- 配套：闭集是**清单 + 一条命令稽核**（启动时打印实际工具面与白名单的差集，每轮打印剪枝结果）。AstrBot 侧已验证此模式（2026-09-23 起：白名单 **22 项** / 每轮摘掉 **3 个**系统注入工具；文件四件套已还给聊天门）。
- **路径保险已否（2026-09-23 主人拍板）**：不做「只允许在她自己的目录动文件」那层 allowlist ——「我在提示词里面写严了就够了」。所以文件工具的边界**只写在人格里**（两侧同款《碰文件的规矩》）：只在主人明确给文件 / 明确要写东西时才碰；不碰系统与配置目录、别人的数据、记忆库；路径不熟先说出打算再等同意；要跑命令/装东西/动服务 → 派活。**（一句话：文件四件套 = 读/写/改/搜，**路径保险已否**，边界只靠提示词。）**
- **人格与工具面不许互相打脸**：改工具面必须同步改提示词里那句「你没有 X」；发现注入提示词与实际工具面不一致（AstrBot local runtime 每轮无条件注入那段英文），要按**本轮真实白名单逐句校正**，不能整段留也不能整段删。

## 三·补：分段（符号 / 按内容类型分 / 阈值 —— 双侧必须同款）

- 新符号 **`⁂`(U+2042)**；容错集合 **`⁂` / `※`(U+203B) / `⸮`(U+2E2E)** —— 模型万一沿用旧话术也照样切、且符号不会发出去。
- 为什么换：旧符号 `※` 在正常文档正文里也会出现（引用注记），会被通道层误切成多条。
- 双侧落点：AstrBot `cmd_config.json` 的 `segmented_reply.regex` / `content_cleanup_rule` + 人格正文；Hermes `profiles/chat/SOUL.md` + `hermes_onebot/segmentation.py`。
- **规则只剩一条（2026-09-23 主人拍板）：出现 `⁂` 就切，没有 `⁂` 就整段发。没有长度阈值。**
  - 阈值整条删掉（连配置项 `segment_threshold` 一起废弃）：旧实现抄 AstrBot 的「超过 N 字就不切」，
    结果字数一多（英文占比高时最容易超）不切 → **不切也就不清理** → `⁂` 留在正文里被主人看到（他报的就是这个）。
  - 连带收窄：切分正则里**去掉句末标点与 `$`**（`.*?[⁂※⸮]+|.+`）——否则「不含 `⁂` 的 1000+ 字一条不切」做不到（长文必然有句号和换行）。
  - 段间隔 1.5~3.5s、清理 `[⁂※⸮]`、容错符号这些没动。
- **分段按内容类型分**：**短对话（聊天 / 回话 / 吐槽 / 问答）→ 每条末尾写 `⁂`**；**长内容（清单 / 文档 / 报告 / 代码 / 步骤 / 列举）→ 一个 `⁂` 都不写、整段发**。
  旧版是「每条短消息末尾写 `⁂`」+「整条总长别超过 150 字」，她就连清单/文档也往里塞符号。
  现在长内容整段发**靠「她不写符号」**实现，不靠长度；人格里还要写清「只有 `⁂` 会切」「分隔符是给系统的、主人看不到」，免得她担心格式。
- **硬红线：`⁂` 任何情况下都不许出现在主人收到的消息里** —— `segmentation.scrub()` 兜底（正则坏掉时退回逐字符过滤），
  适配器在 `send()` 与 `_send_one()` 两道都洗，覆盖 `segment_enabled: false` 这类降级路径；整条只有分隔符 → 不发（旧版会退回原文把 `⁂⁂⁂` 发出去）。
- 适配器与 AstrBot 的**有意不同**：AstrBot 不分段时把 `⁂` 原样发出去（正是主人看到的现象），Hermes 侧一律先洗再发。

## 四、会话连续性（自写适配器的隐藏地雷）

- **会话 id 一次定死**，禁止每句新开：私聊 `qq-private-<uin>`、群聊 `qq-group-<gid>`（群内再按发送者区分缓冲）。
- 验收：连发 100 句不"失忆"；重启适配器后会话仍在。
- **切换前必须迁移历史**：AstrBot `data_v4.db` 里的对话要迁进 Hermes 会话，否则切换当日她失忆。
- 记忆三层不迁移（共用同一 Hindsight bank：`mianmian-history`）。

## 五、可发现性（"坏了要能马上知道"）

- 官方健康入口优先；不够才写最小脚本（一条命令查全部：双侧门、A2A、Hindsight、插件在位、补丁在位、参数是否被改回）。
- **告警分级**：能自愈的不吵人；需要人干预的才推送。全都告警 = 没有告警（告警疲劳）。
- 检查项必须包含"参数漂移"：如防抖 `wait=10.0s`、常驻记忆开关、工具白名单、补丁在位。
- 日志不得含消息正文与凭据。

## 六、位置与取舍

- 通道层（通道/分段/防抖/协议端）留在**能连小号的地方**；大脑、记忆、技能、工具面放 Hermes。
- 正式形态：Hermes 平台插件（profile plugins 目录、持久卷、不额外起进程、不装系统依赖、升级不被覆盖）。
- AstrBot 容器**暂不删除**：既是参照样板，也是将来群聊玩法可复用的现成件。

## 七、判据（"算不算成功"）

1. 像人：盲评优于现状，且能指出具体是哪几句变好了。
2. 够用：单步查询她自己做完；多步活派得出去且回得来。
3. 结实：异常能自己冒出来，不靠人翻日志。
4. 干净：不新增常驻进程、不新增系统级依赖、补丁数量只减不增。
