# 今天踩过的坑与规则（2026-09-23）

> 一页纸，只写**规则 + 为什么 + 怎么验证**。背景流水账在 `ops-changelog/README.md` 与各技能 references 里。
> 今天这场折腾：把 QQ 小号(<BOT_QQ>) 的聊天通道从 **AstrBot 直连** 换成 **Hermes 聊天门自写的 `hermes_onebot` 适配器**；AstrBot `docker stop`（容器保留、随时可开）。

## A. 通道切换

**A1｜切换只改协议端一个 url，被切走的一方一字不动。**
- 为什么：协议端（NapCat）是**主动外连的客户端**，只认 `network.websocketClients[0].url`。旧侧零改动 = 回退点天然在位，回退从「两处改动要重验」退化成「改回来 + 重启」。
- 怎么验证：改前 `ss -ltnp | grep -E "6199|6700"` 旧口有人在听；回退一句话要能写出来：「url 改回 `ws://127.0.0.1:6199/ws` + `docker restart napcat`」。

**A2｜开通要过两条闸门，少一条就是「看着开了没反应」。**
- 为什么：Hermes 平台插件里 `plugins.enabled` 决定插件**是否被 import**（不写 `register()` 根本不被调用），`platforms.<name>.enabled` 才决定**是否起监听**。光有 token/环境变量不会自动开平台。
- 怎么验证：日志出现 `[onebot] reverse-WS listener on 127.0.0.1:6700` 才叫插件+平台都过了。

**A3｜验证三连，缺一不可（都要真日志，不能只看配置）。**
- ① `reverse-WS listener on …` ② `client connected from …` ③ 真发真收：`inbound message` → `response ready … session=agent:main:onebot:dm:<qq>` → `sent N segment(s)`，`consecutive_failures=0`。
- 怎么验证：自检用**带依赖的 python**——本机 `doctor.py` 必须 `/opt/hermes/.venv/bin/python`，系统 `python3` 没有 `yaml`，会把配置项误判成「未启用」（假红）。

**A4｜换大脑之前必须先迁历史。**
- 为什么：AstrBot `data_v4.db` 里的对话不迁进 Hermes 会话，切换当日她就失忆（本次**未迁**，已如实告知主人）。记忆三层不用迁（共用 Hindsight bank `mianmian-history`）。
- 怎么验证：连发 100 句不失忆；适配器重启后会话仍在。会话 id 只用 QQ 号/群号推，**禁带消息级随机量**。

## B. 先找官方扩展点

**B1｜Hermes 平台适配器本身就是「插件形态」，接平台不用另起进程、不用装系统依赖。**
- 为什么：插件住 `$HERMES_HOME/plugins/<name>/`（注意是**该 profile 的**目录）+ `plugins.enabled` + `platforms.<name>`；只 import 公开模块、不改框架源码 → 住在数据卷里，**升级/重建都吃不掉**。
- 怎么验证：`config.yaml` 里开关改了有效；插件目录在 `/opt/data` 挂载树内；`grep -rn "<能力>" /opt/hermes` 与官方文档各查一次再下「不支持」的结论。
- 对照：容器内改源码的补丁式做法重建必丢，得配自愈入口 + 登记（见 D4）。

## C. 告警设计（今天最贵的一课）

**C1｜告警通道绝不能依赖被退役/被切换的一方。**
- 为什么：告警当时走旧框架插件的 `127.0.0.1:8098` 接收端；平台一搬走，它发消息必然失败——**线上实测 HTTP 500**，告警静默丢失，正好在最需要它的一天。
- 怎么验证：故意失败一次真发告警，判据是**投递台账有 `delivered to …` / 主人引用回了那条消息**，不是脚本退出码。

**C2｜告警要分级：能自愈的不出声。**
- 为什么：全都告警 = 没有告警（告警疲劳）。健康→空输出静默；恢复→只写日志；**同一异常签名**（异常项名集合，不含会变的读数）持续时退避（本机 8 轮≈4h 才二次提醒）。
- 怎么验证：本机用 Hermes 官方 cron 的 `--no-agent` 脚本模式（stdout 原样投递、空 stdout = 静默 tick）；`hermes cron list` 看 job 状态 + 网关日志 `empty stdout — silent run`。

**C3｜切换后旧底座要「降档」，不是继续当故障报。**
- 为什么：AstrBot 退役后收不到消息，会持续产生「平台未连接/平台类 ERROR」残响；不降档就每 30 分钟误报一次。
- 怎么验证：`health_all.py` 里该组检查按「退役待命」出结论，且不触发告警。

**C4｜体检项必须包含参数漂移。**
- 为什么：防抖窗口、工具白名单项数、补丁在位、常驻记忆开关，这些最容易在别处被改回旧值。
- 怎么验证：`python3 /opt/data/scripts/health_all.py` 期望 `✅ 29/29`。

## D. 子代理长任务

**D1｜中途被余额/额度打断 ≠ 白干：续做前先读它的 live transcript。**
- 为什么：每个子代理都在 `/opt/data/cache/delegation/live/<id>/task-0.log` 留逐条过程记录，成果通常已落盘；重跑等于把已花的 token 丢掉。今天实测一个子代理被 `HTTP 402 Insufficient Balance` 掐断前，已经把适配器写完并通过 111 个单测，只是最后报告没吐出来。
- 怎么验证：`grep`/`tail -25` 那条 log 取关键段（别整篇读）+ `find <产出目录> -newermt '-40 minutes' -type f` 盘产出 + 跑一次健康自检确认没被留在半路；续做的任务书里写明「先读那份记录，只做差的那几步」。

**D2｜并行子代理必须划定文件边界，可写文件集两两不相交。**
- 为什么：今天两个并行子代理同时改 `health_all.py`、又同时动同一份人格文件，互相覆盖、都以为做完了。
- 怎么验证：任务书里写死「你只准改 A、B 两个文件，其余只读」；改同一份共享产物（人格库/config/在线服务）时**宁串行不并行**。

**D3｜长任务切小、主任务优先。**
- 为什么：主人原话「可以顺手做别的，但我的要求肯定要先完成」；跑得越久撞额度/上下文上限的概率越高。
- 怎么验证：任务书里**禁写「顺便把别的也改改」**；阶段成果先落盘（文件/提交/配置生效即算，报告可后补）；顺手项单列或另起一个子代理。

## E. 陪伴型提示词（特调，不是强度档位）

**E1｜陪伴型与干活型是两种形状，不能把工作型 SOUL 搬过去当聊天人格。**
- 为什么：形状不对就会变成「带聊天腔的工作规则书」。对照：规则少 vs 多、示例必须有 vs 可无、写节奏 vs 不关心、不给结论 vs 结论先行、工具面窄 vs 全开、常驻事实+按话题召回 vs 再加工作日志。
- 怎么验证：改完按会话读**落库的 system prompt**（`system_prompts.prompt`）里的**内容标记**（新旧各 2–3 个只在某版出现的短语），别用长度/时间戳。

**E2｜工具面窄一点，语气就干净一点；工具 schema 每轮都算钱也算语气。**
- 为什么：实测人格+工具约 **9,273 token**；每多一个工具多一分汇报腔。判据是「能不能一步做完」——查询/看东西/记忆/说话自用/文件四件套留，shell、解释器、子代理编排、运维类砍。
- 怎么验证：`GET /v1/toolsets` 对实际工具清单；结构性成本只看**单次调用**的 `prompt_tokens`（多工具回合是累计值，拿来前后对比会得出「改完反而贵 8 倍」的错结论）。

**E3｜人格与工具面不许互相打脸。**
- 为什么：工具删了而人格还写着「走 a2a 派活」→ 实测她会**谎称已经派了**。
- 怎么验证：改工具面时同步改人格里「你没有 X」那两句；发现框架注入的提示与真实工具面不一致时，**按本轮真实白名单逐句校正**（不能整段删、也不能整段留）。

**E4｜分隔符不能选正文里会出现的符号。**
- 为什么：旧符号 `※` 在正常文档正文里也出现（引用注记），发文档会被通道层误切成多条 → 换成 `⁂`(U+2042)，容错集合 `⁂`/`※`/`⸮` 留着；清理层与切分层必须配套（只加清理=永远不切）。
- 怎么验证：走**真身**的切分自测（真装饰器 + 线上配置）：含 `⁂` 的文本切 3 条、`※`/`⸮` 同样切且不漏、无分隔符不切、换行不切、超阈值整段不切。

## F. AstrBot 时代的坑（已退役，多数通用）

**F1｜人格白名单挡不住框架每轮硬注入的工具和提示。**
- 为什么：local runtime 每轮无条件塞 shell/python/shell_session/文件类工具，还往 `system_prompt` 加一段「你能跑 shell 和 Python」的英文。`persona.tools` 管不到它们。
- 怎么验证：插件在 `on_llm_request` 里按白名单逐个 `remove_tool()`，每轮日志出现「本轮摘掉 N 个白名单外工具」；提示词那段**逐句**校正后，shell 句消失、workspace 相对路径句保留。

**F2｜`persona.tools` 的 `None` 与 `[]` 不是一个意思。**
- 为什么：`null` = **全量工具**（默认值），`[]` = **一个不给**。填错的症状是模型自称「够不着/没权限」，不报错。
- 怎么验证：启动日志的「白名单稽核」行把项数打出来（今天为 22 项）；新增插件工具必须同步加进白名单，否则只有一行日志。

**F3｜容器内源码补丁会被升级/重建吃掉。**
- 为什么：代码在 `/AstrBot`（不在卷里），配置与人格在 `data/`（在卷里）——两者命运不同。
- 怎么验证：补丁走「载荷挂载 + entrypoint 先幂等重打再自检」；重建后 `verify_patch.py` exit 0、boot log 有 `PATCH_OK`。**补丁会自愈，插件 pip 依赖不会**：依赖在可写层，重建后串行重装，期间平台适配器没起 → 整条链路停摆（实测卡死 10 分钟）；处置是把出问题的插件 `mv` 到 `plugins_disabled/` 再重启。

**F4｜人格提示词的段落正本必须入库。**
- 为什么：写库脚本按「段落范围整段替换」，手改库里那份下次就被覆盖。
- 怎么验证：正本在插件目录（如 `plugin/hermes_lookup/persona-boundary-section.md`），改脚本先 `--dry` 看要改什么，改完再读回校验。
